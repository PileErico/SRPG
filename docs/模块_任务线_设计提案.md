## 0. 需求锚点与硬约束（已有真值，只指针不复述）

- 🔒 结构＝**一条解锁区域的主任务线 + 多条支线**；任务线选择影响派系关系（助帝国镇压 vs 助蜥蜴人反抗）——meta §1.7。
- 🔒 定位＝大地图区域解锁 + 自由移动长线单周目（CLAUDE.md 头部）。
- 挂点已全就绪（模块_任务线.md 上半表）：EventEngine when/do、WorldState 持久 flag、对话 set_flags+rep、FactionDB.add_rep、LocationDB+讨伐闭环（BattleSetup.context.location_id）、ws.kill_stats、多图切换挂点（大地图下半）。
- 硬约束：任务状态**必须可序列化**（meta §2 根依赖 0——存档 schema；WorldState 随档落盘先例照走）。

## 1. 核心取向（提案）：任务＝数据驱动状态机，**复用 EventEngine 不造第二引擎**

EventEngine 已有 when 评估/闸门/世界持久 fired/动作注册表（宿主原语 add_rep/set_flag/give_item/dialogue/start_battle 全齐）。任务系统只补两块它没有的东西：**多阶段串行的目标状态机** + **玩家可读的日志呈现**。

- `QuestDB`（data/quests.json；DB 范式：preload+static、`reload_data`、`_path_override` 测试缝）。
- 运行态 `WorldState.quests = {quest_id: {stage: int, done: bool, counters: {}}}`——随档落盘，快照口径与 event_* 同族。
- 推进＝**检查点驱动非轮询**：抵达地点 / 战斗结算 / set_flag 写入 三个 hook 处各扫一次进行中任务（数量级小，无性能题）。

## 2. quests.json schema 草案

```jsonc
{
  "id": "side_bandit_purge",
  "name": "剿灭黑水匪帮",
  "line": "side_borderland",        // main | side_<线名>；同线内任务按数组序串行
  "accept": {"dialogue_flag": "accept_bandit_purge"},   // 接取条件（D4）；主线缺省＝自动激活
  "desc": "哨站商路被劫掠……",
  "stages": [
    { "id": "s1", "desc": "剿灭黑水营地的匪徒",
      "objectives": [                                   // 数组内 AND（词表见 D1）
        {"kind": "kill_count", "tag": "bandit", "count": 5},
        {"kind": "reach_location", "location": "loc_bandit_camp"}
      ],
      "on_complete": [                                  // 直接复用 EventEngine 动作词表
        {"action": "add_rep", "faction": "empire", "delta": 10},
        {"action": "give_item", "item": "gold", "count": 200},
        {"action": "set_flag", "key": "borderland_safe", "value": true}
      ] }
  ]
}
```

## 3. 各决策点展开

### D1 目标词表首发集
提案 v1 三种：`reach_location`（抵达/进入地点——Overworld 交互点现成）、`kill_count`（tag/proto 过滤计数——战斗结算 hook 汇报）、`flag`（读 WorldState flag——**对话/事件推进任务的万能接口**，对话 do 已能 set_flag）。
`item_deliver`（交付道具）/`talk`（对话糖＝flag 的特化）＝v2。护送/限时＝v3（依赖失败态）。

### D2 击杀计数归属
提案＝**接取后增量计**：stage 激活时把当前 `ws.kill_stats` 相关项记入 `counters` 基线，完成判定读差值——防「接任务前杀的也算」（BB 同款手感）。全局账 `kill_stats` 本身不动（图鉴/成就照读）。

### D3 主线区域解锁的机制表达
提案＝**flag 为机制、区域表消费**：解锁一律 `set_flag("region_<x>_unlocked")`；区域系统（门/边界/多图入口）查 flag 决定通行。任务侧不长区域逻辑（单向依赖：区域读 flag，任务写 flag——两模块零耦合）。`unlock_region` 语法糖不做，省一条双写路径。

### D4 任务获取
提案：**主线＝自动串行激活**（上一条 done → 下一条 active）；**支线＝对话选项/地点交互接取**——对话 do `set_flag accept_<id>` → flag hook 扫描激活。零新 UI：接取动作长在既有对话/地点交互里。

### D5 失败态
提案 v1 **不做**（全成功向；未完成＝永远挂着）。失败/限时/互斥后果＝v3 一起做（需要时钟 hook + 日志「已失败」分组，成本集中）。

### D6 互斥线（助帝国 vs 助蜥蜴人）
提案＝line 级 `exclusive_with: ["side_lizard_rebellion"]`：接取/激活一条线时另一条整线标 locked（日志隐藏或灰显）。比逐任务互斥 flag 干净；v2 落地（v1 先单线跑通）。

### D7 区域解锁 v1 范围
提案：v1 **只做任务状态机+日志**，区域门（虚线边界/不可通行/多图切换）等**大地图多图轮**一起做——那边有独立施工档且美术依赖（边界表现）。任务侧只保证 flag 写出去。
（替代案：v1 就做单图内区域门——若你想先看到「解锁」的体感，成本＝通行判定+边界绘制两点。）

### D8 QuestEditor
提案 v1 **不建**：任务数量级远小于物品/技能，quests.json 手写 + **lint 规则9**（引用完整性：location/proto tag/item/dialogue/faction/flag 键风格）兜底。内容量上来若手写痛，再按 ListEditorShell 惯例补编辑器（外壳现成，半天级）。

## 4. 运行时形状（实现时的落点，供评估成本）

- `QuestDB.gd`：静态读 quests.json；`active_quests(ws)` / `stage_of(ws, qid)` 纯查询。
- `QuestEngine.gd`（或并入 QuestDB 静态方法——倾向独立，职责＝推进）：
  `notify_location(ws, loc_id)` / `notify_battle_end(ws, kills)` / `notify_flag(ws, key)` 三个检查点入口 →
  扫进行中任务 stage objectives → 全绿则 `EventEngine.execute_action` 逐条跑 on_complete → stage+1/done。
  宿主（Overworld/Sandbox 结算处/WorldState.set_flag 广播）各加一行调用。
- UI：Overworld 侧 📜 任务面板（事件面板样式先例）：进行中（主线置顶）/已完成两组；当前 stage desc + objectives 勾选态。地图目标标记＝v2。
- 测试：headless 套件（fixture quests + `_path_override`）：接取/推进/AND 判定/增量计数/on_complete 动作/串行/存档往返。

## 5. 分期（提案）

| 期 | 内容 | 验收 |
|---|---|---|
| v1 | QuestDB+schema+状态机（D1 三词）+on_complete 复用+任务日志面板+lint 规则9+**1 条验收支线**（讨伐营地——讨伐闭环现成） | 接→杀→交任务全链可玩，存档往返 |
| v2 | item_deliver/talk/接取对话糖批量化/地图追踪标记/互斥线（D6） | 助帝国 vs 助蜥蜴人可分叉 |
| v3 | 失败态/限时（时钟 hook）/护送；主线区域门联动（随大地图多图轮） | 主线首章「解锁东境」 |

## 6. 勘察项（写实现前需确认的现状，非决策）

- Overworld 地点交互点的回调形状（notify_location 挂哪）；WorldState.set_flag 有无广播缝（无则加一行）。
- 战斗结算回大地图的路径上 kills 数据形状（`_battle_kills` 与 ws.kill_stats 的交接点）。
- 存档 schema 给 `ws.quests` 留位（读旧档缺键＝空表安全，同 ews_state 先例）。
