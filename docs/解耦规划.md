# Sandbox 解耦规划（战略草案 🟡）

> 状态：**🟡 规划草案**——只记「往哪走 / 分几期 / 护栏」，**不含执行细节**（具体怎么改另开窗口专门理）。
> 缘起：`Sandbox.gd` 已 ~2500 行，感知+天气又撑大一圈；讨论「高度耦合能否解、还是本就该这样」的结论记录于此。
> 关联：[路线图.md](路线图.md)「🔧 技术债 · 巨石拆分」、[架构.md](架构.md)。

## 1. 诊断：两种耦合，命运不同

- **固有耦合（别去解）**：战棋战斗本质是一堆强相关状态——AI/感知/寻路/战斗都依赖「同一份 battle state」（单位位置、地形、回合）。这是领域固有，无法也不该消除。
- **意外耦合（要解的病）**：`Sandbox`（一个 `Control` 节点）**同时当了 Model + View + Controller 三个角色**，且子系统直接伸手进它的私有字段：
  - **Model**：battle 数据+规则（units/tiles/turn/vision/weather + 移动成本/LOS/伤害结算）
  - **View**：场景节点 / UI / canvas / 动画
  - **Controller**：输入 / 回合·AI 编排

  → 「状态互相依赖」是固有的；「把三者塞进一个 UI 节点、子系统穿透访问」是意外长歪的。**解耦只解后者。**

## 2. 目标架构：抽出 `BattleState`（纯数据模型）

**核心杠杆**：把「战斗状态 + 规则」从「Sandbox 节点」剥离。

- `BattleState`（纯 `RefCounted`，**非 Node**）：持有 units/tiles/turn/vision/weather + 纯查询/变更方法（`tile_at`/`has_los`/`move_cost`/`advance_turn`…）。**不认识 canvas / UI。**
- `Sandbox`（Control）：持一个 `BattleState`，只管 输入/UI/动画/渲染；规则一律委托给 model。
- 子系统（AI / 寻路 / 感知）操作 `BattleState` 这个**明确接口**，而非伸进 UI 控件。

> 反模式（要避免）：只把子系统搬进「带 `host` 引用的辅助类」——那只是换地方堆同一坨乱麻，模块仍反手够 host，**耦合没减**。搬家 ≠ 解耦。

**解耦白送的能力**（按【正统 SRPG · 战役】方向排序）：
- **存档 / 战中 suspend / 章节间存档**（model 可序列化）——**正统 SRPG 战役的刚需**（FE/FFT 皆有战中挂起存档），是本解耦最强的驱动。⚠️**审计校正（2026-07-02）**：存档**并非「model 白送」**——现有两套序列化（`MapIO` 地图定义 / `UnitFactory` proto）都**刻意重置运行态**（`make_unit` 末 `init_vitals` 注满 HP/armor、`learn_skill` 重置技能 cd/uses），战中 units 根本不落盘。要战中一致必须**从零补第三层「活 Unit 运行态序列化」**，硬前置见下方 §3。
- 纯逻辑**可独立 headless 测**（不必 `new Sandbox()` 拉半个场景）——复杂战斗规则的正确性保障，与体裁无关。
- （无头批量模拟 / 自动战斗 / 联机 = 肉鸽·对战向；已转正统 SRPG，**基本不需要**，不作为驱动。）

## 3. 前置决策（方向已明：正统 SRPG）

**体裁校正 🔒（2026-07-01）**：项目**已放弃肉鸽路线、转向正统 SRPG（战役 + 养成）**。据此重估「解到多深」：

- ✅ **存档 / 战中 suspend / 章节存档** → **正统 SRPG 战役刚需，大概率必做** → **`BattleState` 值得**，是主驱动。**🔒 驱动力校正（2026-07-02，用户拍板）**：战中存档定为**「临时存档（suspend）」语义**——只为退出后继续、非 SL 读档，且**可裁剪**（麻烦就不提供）；campaign 存档（meta 层根依赖）**不需要 BattleState**（见 [meta架构规划.md](meta架构规划.md) §2 两层分离）。故 BattleState 的紧迫性进一步后置，其先导投资＝meta 规划 M1 的 uid 体系 + M5 的 BattleIO 契约。
- ✅ **规则 headless 可测** → 与体裁无关的正向收益，顺带白送。
- ❌ 无头批量模拟 / 自动战斗 / 联机 → 肉鸽·对战向，**转 SRPG 后基本不需要**，不作为理由。

**结论**：方向已足以支撑「往 `BattleState` 走」——因为战役 SRPG 迟早要存档（尤其战中挂起）。但仍**用绞杀者分步、不 big-bang**（见下）；**Phase 0 纯几何可立即做**、`BattleState` 骨架待存档系统排期时同步推进。

**🔎 全局审计发现的 BattleState 硬前置（2026-07-02，做骨架前必须先解决）**：
- **活 Unit 运行态序列化对**：新增 `unit_to_battle_state`/`apply_battle_state`——存 HP/armor/ap/move_points/effects/modifiers(全量非仅装备)/skills{cd,uses}/ai_aggroed/col/row/flying/tags，**复原路径必须绕开 `init_vitals` 注满与 `learn_skill` 充能重置**。
- **稳定 unit id**：`turn_order`/`zoc_triggered`/AI 引用现在都是 Unit 对象引用，`Unit.gd` 无 id 字段——序列化前必须给每单位分配稳定 id，读档重映射。**（一旦有存档文件就难改，写第一行 `to_dict` 前须拍板 id 生成规则。）**
- **Vector2i 键的 JSON 编解码约定**：`_vis_seen`/`aggro_regions`/`zoc_triggered` 用 `Vector2i` 作键，JSON 不支持——统一 `[x,y]↔Vector2i` helper（`MapIO` 已用 `[[x,y]]` 存 region cells，沿用）。
- **effects↔modifiers 配对不变式**：effects 到期靠 `source` 匹配摘 modifiers——存档须保证两数组一起存/读、`source` 命名一致，否则读档 buff 残留或倒计时脱钩。
- **序列化白名单 = 状态清单的 `serializable_for_save`**：`_time_sight_mult`/`_vis_visible`/`_deploy_cells`/`aggro_regions` 等**派生态别存**（存了会与真值不一致），只 `_vis_seen`(历史累积不可重建)必存。
- **一批「伪纯方法」搬进 `RefCounted` 前必须先拆**：`_resolve_one`/`_handle_deaths`/`_ai_update_aggro`/`_tick_turn_end_effects`/`_recompute_vision` 等都混着 `_push_log`/`canvas.queue_redraw`/`call_deferred` 编排——须改成**返回结构化事件、日志飘字重绘留宿主**，否则会把 canvas 引用带进纯数据模型。

## 4. 分期路线（绞杀者 strangler，高层骨架，不含执行细节）

> 原则：**渐进、任何一步都能停/能验证、绝不 big-bang**。

- **✅ Phase 0 · 纯几何先行（2026-07-02 已完成）**：抽 `HexGrid.gd`（cube 互转/距离/取整器/邻居/连线/环外扩）。Sandbox 逻辑几何 + `HexCanvas.axial_round` 均委托它，删掉 3 个变死的 cube 私有助手。**对拍脚本 `tools/test_hexgrid.gd`（266k 断言 0 失配）**。**去重收益校正**：真正的重复不是「三处同写」，而是 ① `(col-(col&1))/2` odd-q 换算开写 3 处、② `axial_round`(axial)与`_cube_round`(cube)两个等价取整器——现均收敛到单一实现。**两个坑（已规避）**：`line`(cube 插值连线,LOS/寻路)与 `spoke_through`(方向轴,直线AoE)**语义不同、保留为两个 API 不合并**；LOS 的地形阻挡判定含游戏规则、**不进** HexGrid（HexGrid 只出 `line()`，阻挡由消费方走返回格判）。
- **Phase 1 · 埋种子（seam）**：引入 `BattleState` 骨架；Sandbox 只留**薄访问器**委托给它（如 `units` 变成返回 `_state.units` 的属性），**对 SandboxCanvas 的 `editor` 接口尽量零破坏**。此期不搬逻辑，只立"缝"。
- **Phase 2 · 状态迁移**：把 units/tiles/turn/vision/weather 一块块搬进 model，逐块 headless 回归。⚠️搬「伪纯方法」前先按上方 §3 硬前置把它们改成「返回事件、日志/飘字/重绘留宿主」。
- **Phase 3 · 子系统改依赖**：Perception / Pathfinding / EnemyAI / TurnSystem 一个个改成操作 `BattleState`（不再够 Sandbox）。每搬一个，它就变得可独立测。
- **Phase 4 · 收尾**：`BattleState` 可脱离场景独立 headless 测；`Sandbox` 只剩渲染/输入/动画/UI 编排。

## 5. 范围与边界

- **不动**：`Unit.gd`（383 行，内聚、非巨石）。
- **相关但独立的债（并行项，非本规划）**：
  - `MapEditor` 层数据抽象（`Layer` 容器，消除「每加一层改 snapshot/restore/save/load/new 6 处」的复制粘贴——加 `map_environment` 时已踩到）。
  - Dijkstra 性能（缓存 + 二叉堆，地图变大前）。
  - `UnitStatusPanel` / `ItemEditor` 拆分（各 ~1000-1300 行，另账）。
- **明确不做**（overkill）：ECS、全局 event-bus。
