# 编辑器 / 沙盒合并规划

> 把「地图编辑器」与「战斗沙盒」彻底合并成一个**游戏内置编辑器**：编辑地图时即可布置单位 / 触发器、配置各地形数据（通行性 / 移动成本 / effect）、用模板套用地形特殊 effect、新建物品（立绘 + 名字 + tag）。
> 本文档 = 这次大改的**规划 + 设计规格 + 分期路线**。文档分工不变：已做 → 写进 [实现现状.md](实现现状.md)、设计规格在本文档与 [单位系统设计.md](单位系统设计.md)、tag 在 [标签词典.md](标签词典.md)。**做完一阶段 → 在实现现状补、从本文档勾掉。**

## 编辑器 ≠ 沙盒（定位区分 🔒，2026-06-30 校正）
两者**本质不同、不该揉成一个**，但**共用底层**（单位/物品/Unit 这套基建）：
- **编辑器** = **创作「可玩的关卡」**。产出 = 一份持久关卡内容（地形 + 这一关的单位 + 触发器 + 目标…），authoring。**重心 = 让编辑器能把整关布置出来**。
- **沙盒** = **自由测试场**。在已编好的图上随意召唤各种单位/物品，验证机制/手感，testing。**维持独立身份，不并入编辑器。**

➡ 修正：早先「把两者合成一个场景双模式」的框架**偏了**。正解 = **给编辑器装上完整的关卡创作能力**（单位/触发器/地形数据/物品 authoring，复用沙盒已有的单位/物品基建），沙盒照旧当测试场。编辑器的「试玩本关」用阶段 2 的内存直传跑当前关卡；沙盒的自由测试是另一个入口，不混。

## 定调
**这次合并 80% 是「搬运 + 接线」，不是「重写」。** 经全工程精读确认：画布（`HexCanvas` 共享基类）、数据层（四个 `*DB` 静态单例）、坐标系、地图文件桥、造单位工厂（`make_unit`）、单位编辑 UI（`DeployPanel` / `RosterBar`）、区域→部署 / 仇恨链——**全已存在**。真正要从零长出来的只有三样：① 单位 / 触发器写进地图 json；② 地形数据编辑 UI；③ 物品新建 UI。其余是把沙盒侧已有能力暴露进编辑器。

## 已锁定决策 🔒
1. **合并形态 = 一个场景 + 顶层 `mode` 切换**（`edit` / `battle`），内存共享地图数据。不走「两场景共享子树」——全工程 0 处 `instantiate()`、UI 全 procedural，硬拆子场景收益为负。两个 `.tscn` 都是空壳单 `Control`，合并只动脚本、不碰场景文件。
2. **试玩闭环 = 内存直传**：编辑 → 试玩 → 返回，免存盘往返（所见即所玩）。战斗运行时需新增「从内存 dict 装载地图」入口（现 `_load_map` 仅认文件路径）。
3. **起步 = 阶段 0 + 1（单位进地图）**，其余阶段顺延——这是收益 / 成本比最高的一刀，单独就把「每改一场仗都要动 GDScript」变成「拖几下存盘」。
4. **阶段 1 切法 = α 持久化优先**：阶段 1 只动「数据」——用现有沙盒部署 UI 摆好敌 / 我（敌方 / 中立任意放、我方限部署区）→ 存进地图 json → 读回 + 预置敌人加载。**不碰 MapEditor UI、不做 host 抽象，零回归风险。**「在地图编辑里一边画地一边摆单位」随阶段 2 合并场景时自然到位（host 抽象那时只做一次）。

### 阶段 2 — 一个场景双模式 + 一键试玩 ✅ 已落地（2026-06-30）
- **`Game.gd` / `Game.tscn`（统一宿主）**：顶部模式条（主菜单 + ✎编辑 / ▶试玩 互斥 tab），把 `MapEditor` 与 `Sandbox` **作为子场景同时实例化、叠放在同一容器**，按 `mode` 切 `visible` + `process_mode`（隐藏方 `DISABLED`，停其 `_process`/`_input`，避免快捷键/动画串台）。**子场景间零回调耦合**——Game 单向调 `_editor.to_json_dict()` / `_battle.load_from_memory()`。
- **内存直传试玩（决策 B1）**：`MapIO.normalize(dict)`（从 `read_file` 抽出的校验+钳制+逐格兜底）+ `Sandbox.load_from_memory(dict)`（按内存地图重置到布置阶段、保留 roster、重落预置单位）。点「▶试玩」= `编辑器内存地图 → 战斗`，**免存盘**；「✎编辑」切回、编辑器状态原样保留。
- **入口**：`StartMenu` 加「编辑器（编辑 · 试玩）」→ `Game.tscn`。`MapEditor.embedded` 标志隐掉自带「主菜单」（Game 顶栏统一提供）。旧的独立 `Sandbox.tscn`/`MapEditor.tscn` + `.bat` 仍可单跑（`embedded=false` 默认）。
- ✅ headless 验证：Game 启动 edit 模式（editor 15×15 可见 / battle 隐藏）→ 注入预置单位 → 试玩内存直传（battle 15×15 deploy、预置敌@(3,4) 落子）→ 返回编辑保真；Game.tscn / StartMenu 实跑 0 报错。
- **此实现的取舍 / 遗留**：① 采用「嵌入两子场景」而非「单宿主脚本合并 3300 行」——风险最低、复用全部已验证逻辑，代价是两套画布 + 地图数据在试玩时刻同步（非实时共享内存）。② 战斗 HUD（TurnOrderBar）与顶栏的像素级排布是 cosmetic，待打磨。③ 深度宿主合并 + 统一画布仍按阶段 6 收口。

### 阶段 3 — 触发器层（运行时 ✅ 已落地 2026-06-30；编辑器 UI 待做）

## 地图 json schema 扩展草案
> 兼容套路（沿用现状）：**加字段 + 读端 `.get(key, default)` 兜底**，旧 `maps/*.json` 零影响。`format_version` 仅作人读标记、读端不强校验。

```jsonc
{
  "format_version": 3,
  "grid": "hex_flat_oddq",
  "width": 15, "height": 15,
  "tiles":   [ [ {"terrain":"plain","variant":"grassland"}, ... ], ... ],  // [row][col] 行优先（不变）
  "regions": [ {"id","label","color","kind":"aggro|deploy","cells":[[x,y]]} ],  // 不变

  // ===== 阶段 1：预置单位 =====
  "units": [
    { "proto": { /* _unit_to_proto 输出：name/four/trait/equip/skills/ai_*/stats… */ },
      "col": 10, "row": 7, "faction": "enemy" }   // faction 覆盖 proto.default_faction
  ],

  // ===== 阶段 3：触发器（草案）=====
  "triggers": [
    { "id":"trig_1", "label":"伏兵",
      "when": { "event":"enter_region", "region":"region_1", "by_faction":"player", "once":true },
      "do": [ {"action":"spawn_unit","unit_ref":"…","at":[12,8]},
              {"action":"activate_aggro","group":"g1"},
              {"action":"show_message","text":"…"} ] }
  ],

  // ===== 阶段 4：图级地形覆盖 + effect 模板（草案）=====
  "terrain_overrides": { "forest": { "move": {"cost": 3} } },   // key="terrain/variant"
  "effect_templates":  { "tpl_burning": { "label":"燃烧","tags":["flammable","hazard"],
                          "effects":[ {"name":"灼烧","when":{"occupant_lacks_tags":["fire_immune"]},
                                       "grant":{"stat":"HP","layer":"dot","percent":-5,"nature":"debuff"}} ] } },

  // ===== 远期：实例级 tag（稀疏，key="x,y"）=====
  "cell_tags": { "10,7": ["on_fire"] }
}
```

**坐标序的坑（务必记牢）**：`tiles[row][col]`（行优先） / `regions.cells[[x=col,y=row]]` / `units[].col,row`（odd-q）。新字段统一显式 `{col,row}` 或 `[col,row]`，别再踩反序。

## 风险与坑（带行号）
1. **层数据未抽象**：`tiles`（[MapEditor.gd:47](../MapEditor.gd#L47)）/ `regions`（:55）是独立成员，每加一层要在 `_snapshot`/`_copy_*`/`to_json_dict`/`load_from_file` 等 6 处各写一段，漏一处=不能撤销或不落盘。阶段 6 前加层须照抄区域那套抄全。
2. **单位全硬编码、地图不含单位**：`_spawn_units`（[Sandbox.gd:227](../Sandbox.gd#L227)）+ `ENEMY_ROSTER` + 一堆常量。MapEditor 完全无 `units` 成员（从零起）。
3. **R 重开 / exit_battle 依赖 roster**（[Sandbox.gd:1135](../Sandbox.gd#L1135)）：改存档驱动后须从地图 units 重建。
4. **两份地图解析已分叉**（钳制策略不同，见阶段 0），合并 `MapIO` 时统一。
5. **三套坐标序并存**，极易踩反（见上）。
6. **四个 *DB 全只读、`_loaded` 一次性**：地形 / 物品编辑依赖热重载，`ItemDB` 引用的 `armor.json`/`accessories.json` 不存在（靠 `file_exists` 兜底跳过）。
7. **tag 词表是 markdown、机器不可读**：`docs/标签词典.md` 真值，但 `TAG_CN`/`RARITY_COLORS` 是 UnitStatusPanel 里硬编码副本手动同步。「编辑器选 tag」需先把词典转 json。
8. **特性稀有度字段不一致**：物品稀有度在 `tags[]`、特性在 `rarity` 字段。`triple_vs`（屠龙者×3）数据有、逻辑未实现。
