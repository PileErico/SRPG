# 地块美术升级——🟡 设计草案（2026-07-02，讨论用，敲定后逐项标 🔒）

> 输入：用户给的边线河流参考图（经典 hex 大地图：河沿六边形**边**流动、道路红虚线、领地黑虚线、地形靠底色+图标）+ 用户观点：**极简风格正确且可行；适度美术升级＝更多地形刷 + 增强表现层；大世界与战场比例尺不同，地形刷不该全部通用**。
> 已做可视 mock（在现有大地图上实画）：[边线河流mock.png](边线河流mock.png)——蓝=边线河（行带分隔边收集，天然连续蜿蜒）、棕块=桥点、红虚线=道路 overlay。约 60 行画布代码，技术上无障碍。

## 1. 边线河流：怎么看 + 是否采纳（建议：采纳，大地图专属）

参考图的做法本质是把地图特征分成两类：**面特征**（地形，占格）与**线特征**（河/路/边界，沿边或跨格）。我们现状全是面特征（水=water 地块、路=road 地块）。

**为什么大地图适合边线河：**
1. **比例尺对**：大地图一格≈数公里，河宽远小于格宽——河占整格既失真又**吞掉一格地形**（那格不再是草原/森林）。边线河让格保持地形身份，河变成格间特征。
2. **玩法语义天然清晰**：河=移动阻隔，过河=桥/渡口（**边属性**）——桥成为战略要地（BB 的桥伏击战！我们的 enter_tile 事件在桥格挂遭遇天然成立）；「沿河设防」「河划分势力圈」都顺出来。
3. **接区域解锁**：河+山脉=区域边界的最佳视觉表达（M4 剩项「区域解锁」正好要边界表现）。

**为什么战场不适用（用户判断正确）**：战场一格≈几米，河就是可涉水/阻挡的**面**——现有 water 地块语义就对。→ **边线河=大地图专属层**，不进战场，正是「两比例尺地形刷不全通用」的第一个实例。

**成本盘点**（按依赖排序）：
- 数据：地图 schema 新增线特征字段。建议**格对表示**（最直白、无方向枚举歧义）：
  `rivers: [{id, label, pairs: [[[x1,y1],[x2,y2]], …]}]`——每项=一条相邻格对的共享边；运行时建 `{归一化边键: river}` 索引。编辑器作者体验=「河刷」：点击/拖过两格间的边即画/擦。
- 渲染：HexCanvas 已有 `hex_corners`——共享边=两格公共顶点连线（mock 即此法），粗线双色（深衬底+亮水面）即可保持极简线稿风。
- 编辑器：新叠加层「线特征层」（画河/擦河；桥=边上的点属性）。
- 寻路（玩法期才做）：`find_path`/Dijkstra 目前只看**目标格**成本，需加「跨边查询」——跨河边=阻断（需桥）或高成本（涉渡）。**表现层先行、玩法层后接**，两期拆开互不阻塞。

## 2. 同一思路的推广：线特征 overlay 通道（河/路/边界 三件套）

参考图的红虚线道路提示了另一件事：**我们现在的 road 地块也吞地形**（mock 里 row 8 那条土路 vs 红虚线一对比很明显）。若引入线特征通道，可一并考虑：
- **河**（边线，实线）——§1。
- **路**（格心连线，虚线 overlay）——路径下的格保持草原/森林底色；道路的移动折扣改挂在「沿路移动」上。⚠️ 迁移成本：现有 road 地块的 cost 语义要换轨，动 Dijkstra——**远期，待定**；短期 road 地块照旧能用。
- **边界**（区域描边，黑/派系色虚线）——**成本最低收益最高**：大地图 `regions` schema 已存在（编辑器区域层现成），只差「沿区域外轮廓画虚线」的渲染；直接服务区域解锁/派系领地可视化。

## 3. 地形刷分层（大世界 vs 战场）

现状：`terrains.json` 一张表两边共用。问题：战场语义（掩蔽/挡视线/effects）对大地图无意义；大地图要的宏观地貌（丘陵/沼泽/农田/冻原/海岸）战场也不该出现在笔刷栏。

- **方案 A（推荐）**：terrains.json 每条加 `scope: "battle"|"overworld"|"both"`（缺省 both，旧数据零迁移）——TerrainDB 加 `by_scope()`，**编辑器笔刷栏按当前地图 map_type 过滤**。保住「地形单一数据源」约定，改动最小。
- 方案 B：拆 terrains_battle.json / terrains_overworld.json——更彻底但破坏单一源约定、MapIO/TerrainDB/编辑器全要动。除非 A 用出混乱再升级。

首批大地图专属地形刷候选（描边线稿风 decor 已有 12 种画法可参考）：丘陵（缓弧）、沼泽（苇草+水点）、农田（田垄横线，参考图同款）、冻原（雪点）、海岸浅滩。

## 4. 表现层微升级（不破坏极简）

1. **decor 变体扰动**：同地形每格 decor 的数量/偏移用「格坐标 hash」做确定性微扰动（零数据、零存档冲击，去掉现在的印章感）。
2. **大地图 decor 补齐**：§3 新地形刷各配一个线稿 decor；地点旗帜/动态单位 token 已有（M7/WorldSim）。
3. **战场侧维持现状**；同样可吃 decor 扰动。
4. 远期候选：地形过渡边（同色系深浅渐变边）、季节/天气调色板（EnvDB 已有 tint 通道）。

## 5. 建议实施顺序（全部待用户拍板后动工）

- **P1 低成本高感知**：decor 坐标扰动 + terrains `scope` 过滤（方案 A）+ 大地图新地形刷 3~5 个。
- **P2 边线河表现层**：schema（pairs 格对）+ 渲染 + 编辑器线特征层（画河/桥点）。
- **P3 玩法语义**：跨河阻断/桥 + 区域边界虚线（接区域解锁）+（远期）道路 overlay 化换轨。

## 6. 待定（勿自行实现）

2. 地形刷分层选 A（scope 字段）还是 B（拆文件）。
3. 道路是否 overlay 化（动寻路，迁移成本最高的一项）。
4. 新地形刷清单与数量；decor 扰动的幅度。
5. 区域边界虚线的语义（纯视觉 or 显示解锁状态/派系色）。
