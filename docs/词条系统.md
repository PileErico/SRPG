# 词条系统 / 装备生成（🟡 草案）

> **状态：🟡 草案——短期不做。** 先导入基础物品（白板），等做**锻造 / 铁匠**那轮再敲定、标 🔒。
> **目标**：素材有限下，用**词条**而非新美术给装备（尤其**防具**）制造差异——同一张图、不同词条＝不同价值。
> **复用**：词条 = 修正对象（modifier），走既有[装备 / 修正管线]（见 [单位系统设计.md](单位系统设计.md)、[实现现状.md](实现现状.md)）；tag 驱动（稀有度见 [标签词典.md](标签词典.md)）。路线图「肉鸽框架」已列「装备 / 词条（tag 驱动的效果系统，复用修正管线）」——本篇即其展开。

## 一、核心模型：一件装备 = 白板 + 两维词条来源

普通装备默认是**白板（common）**、无词条。差异来自**两条独立的词条来源维**：

| 维度 | 来源 | 词条性质 | 归谁管 |
|---|---|---|---|
| **稀有度**（rarity） | 生成时 roll | **正面**词条（越高稀有度 → 越多/越强） | 重铸（玩家转移） |
| **状态**（condition） | 生成时 roll | **负面** / 无 / **正面** | 铁匠（修复 / 强化） |

- **稀有度**：沿用现有稀有度 tag（`common`/`uncommon`/`rare`/`epic`/`legendary`/`special`，互斥取一，见标签词典）。白板 = `common`、无正面词条。
- **状态**：新增的第二维修正槽。**同一件装备的状态是单槽、互斥**——负面（`陈旧的`/`破损的`…）、无、正面（`强化的`/铁匠打磨…）三者取一。
  - 负面状态 → 附带**负面词条**，且**显示稀有度 −1**（见下）。
  - 正面状态 → 附带**正面词条**；**铁匠强化武器本质上就是给它施加一个正面状态**。

---

## 二、生成流程（roll 顺序）🟡

物品生成时按顺序两次 roll：

1. **roll 稀有度** → 得到该稀有度对应的**正面词条**（白板则无）。
2. **roll 状态** → 得到 **负面词条** / **无状态** / **正面状态**（概率分布待定）。

### 显示稀有度 −1（负面状态的表现）
- 带负面状态时，装备的**显示稀有度 = 实际稀有度 − 1**（边框配色、tooltip 抬头都按降一级显示）。
  - 例：一件实为「稀有(蓝)」的护甲带 `破损的` → 看起来像「优秀(绿)」。
- **铁匠修复**移除负面状态 → 恢复真实显示稀有度（词条本身不受损，只是"看起来旧"被擦掉）。
- 语义：破损/陈旧让好货"卖相变差"，修好即恢复——鼓励玩家捡处理"卖相差但底子好"的装备。

## 三、玩家操作

### 重铸（reforge）——转移**稀有度词条**
- 把**一件装备的词条移动到另一件上**。
- 用途：把好词条从不想要的部位/白图，挪到想穿的装备上。
- 待定：能移哪些词条（仅稀有度正面词条？）、部位是否需匹配、有无次数/损耗/失败、目标已有词条如何处理（覆盖 / 叠加 / 需空位）。

### 铁匠（blacksmith）——管**状态**维
- **修复**：移除负面状态（`破损的`/`陈旧的`），恢复显示稀有度。
- **强化**：给装备施加一个**正面状态**（＝正面词条）。
- 推论：状态是单槽 → **要强化得先修好**（负面状态占着状态槽）；一件装备同时"破损又强化"不成立。（待确认是否接受此约束，或状态允许多槽。）

## 四、与现有系统的关系 / 前置

- **词条 = modifier**：直接复用 `Unit.modifiers` + `effective_stat`/eff 桶管线（词条挂 `source`（如 `affix:*` / `condition:*`）+ `nature`（增益/减益），到期/移除/重铸按 source 摘）。无需新伤害数学。
- **稀有度 = tag**：配色、筛选沿用 `TagDB`（见标签词典）；显示稀有度 −1 只影响**呈现层**，不改实际 tag。
- **基础物品先行**：`ItemDB` + `data/*.json` 里的条目是**白板模板**；词条/状态是**生成期附加**、不在物品编辑器手填（编辑器只维护模板本体）。

### ⚠️ 关键前置：物品需要"实例化"
- **现状**：物品是 `ItemDB` 的**共享模板**（按 id 取，`u.equipment` 只存 item_id 字符串）——**无每件独立状态**。
- **词条/状态是每件装备各自 roll 的** → 必须有**物品实例**（instance）承载「模板 id + 本件的词条列表 + 状态」，区别于共享模板。
- 这是本系统最大的结构前置：得先引入物品实例层（背包/装备存实例而非纯 id），再谈生成/重铸/铁匠。归到锻造那轮一并做。

## 五、待定 / 决策点（做那轮再敲定 🔒）

1. **词条池**：怎么定义？预定义词条表（每条 = 名字 + mods + 允许部位 + 稀有度门槛），还是按 stat 程序随机？倾向前者（可控、可 tag 筛选）。
2. **稀有度 → 词条曲线**：每级给几条正面词条、强度如何递增。
3. **状态分级**：负面是否分轻重（`陈旧的` 轻 vs `破损的` 重）？正面强化是否分等级（+1/+2…）？
4. **状态是否单槽**：单槽（强化前须修复）还是负面/正面可并存多槽。
5. **重铸规则**：可移词条范围、部位匹配、损耗/次数/失败率、目标词条覆盖策略。
6. **显示降级呈现**：仅边框色降级，还是加"破损"角标/裂纹图标提示。
7. **实例数据结构**：实例存哪（背包/装备槽存 `{id, affixes:[], condition}`）、如何序列化进存档（依赖肉鸽 meta/存档系统）。
