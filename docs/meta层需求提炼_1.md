## 0. 定位修订

游戏定位介于火焰纹章与战场兄弟之间:火纹式战术战斗 + BB 式沙盒经营。
**放弃线性推进和肉鸽短局循环**,改为大地图区域解锁 + 自由移动的长线单周目结构。
现有战斗层(四属性、修饰符管线、声明式伤害、速度行动队列等)不动,本文档除**死门机制(§1.11,战斗层新增)**外全部是战斗外 meta 层。

## 1. 已确认需求(可纳入架构规划)

### 1.1 大地图层(细化既有设计)
- 大地图为六边形网格,与战斗地图同构。
- 时间仅在玩家移动时流动;可原地扎营(时间流动 + 形成临时据点)。
- 区域随剧情逐步解锁;已解锁区域内自由移动。
- 抵达/经过地块时有概率触发事件。
- **起步路径(复用既有)**:沿用路线图「两种地图」方案——地图库分文件夹(`maps/overworld/` vs `maps/battle/`)+ 地图 schema 加 `map_type` 字段;日夜循环直接复用已落地的 EnvDB `times`(昼/夜)体系,大地图时钟推进即切 time。

### 1.2 事件管理器(在既有触发器框架上生长)
- 战斗侧触发器(schema v3 `triggers:[{id,label,when,do}]`)运行时已落地。大地图事件管理器**不另起炉灶**,扩展同一 when/do 模型:
  - `when` 新增:`enter_tile`(抵达/经过地块)、`timer`(时间间隔)、角色条件等;沿用 `once`,新增**触发冷却**与**全局事件间隔**(战场兄弟式)。
  - `do` 新增:开对话、开战斗、给物品/声望、改世界状态等。
- 事件条件用既有 tag 系统表达(tag 统一判断,项目核心理念)。

### 1.3 地点系统
- 城市/村落:补给、交易、招募、装备维护(铁匠)。
- 野外遗迹/野外据点:可进入;据点定期刷新,提供重复战斗。

### 1.4 营地与职务
- 扎营形成临时据点,内含事务槽位:医生、厨师、工匠、警卫等。
- 玩家指派花名册角色任职,各职务提供不同加成。
- 职务加成的承载方式**待定**(见 §2.2),先不实现具体数值。

### 1.5 人员管理
- 花名册规模 25+,单场部署 6~12。
- 生命值与装备耐久**战斗结束后不自动回复**,随时间恢复:
  - 有医生/铁匠任职:扎营期间消耗资源自动恢复。
  - 无对应职务:生命恢复减速;装备须进城找铁匠。
- 由此产生人员轮替需求(受伤者休整,替补上阵)。

### 1.6 装备系统扩展
**⚠ 关键前置 = 物品实例化**(词条系统.md 已识别):当前 ItemDB 是共享模板——所有同 id 物品是同一条数据。词条、耐久、状态修正、强化次数全都要求**每件装备是独立实例**(实例 = 模板 id + 实例态:词条列表/耐久/状态修正/已强化次数)。此 schema 变更须最先做,且与存档系统(§3 第 0 项)同期设计。

三个正交维度,数据结构上分开:

**a. 稀有度**(普通/稀有/史诗…六档,沿用既有稀有度体系)
- 掉落生成时随机;决定词条数量。
- 用颜色差分表现,不用词缀文本。

**b. 词条(affix)**
- 按物品类型从对应词条池生成;单条词条属性固定不随机。
- 铁匠处可将词条转移到另一件**同类**物品,替换其原有一条词条。
- 转移消耗:**供体装备本身 + 素材 + 金钱**(已确认)。

**c. 状态修正**(与稀有度独立)
- 负面(破旧/残缺…):附加额外负面词条 + 稀有度**显示**-1(实际词条数不减)。
- 正面(精致/豪华…)。
- 铁匠可修复负面状态:移除负面词条、恢复显示稀有度。
- 强化 = 一种正面状态修正,区别是可自选特定词条;每件武器强化次数有限。

**d. 武器耐久度**
- 新增字段;防具沿用既有护甲值。恢复逻辑见 §1.5。

### 1.7 派系与声望
- 玩家与各派系有声望值;敌对后会在大地图遭到攻击。
- 任务线选择影响派系关系(例:助帝国镇压蜥蜴人 vs 助蜥蜴人反抗)。
- 结构:一条解锁区域的主任务线 + 多条支线任务线。

### 1.8 对话系统(新模块,尚未开工)
- 通用对话模块:两侧立绘 + 中间文本 + 玩家选项。
- 两类:纯演出对话 / 带分支影响的对话(影响限于个人剧情、支线走向)。
- 触发场景覆盖全游戏:据点内 NPC 对话、大地图事件对话、**战场内触发**(如敌方单位招募对话,火纹式)。战场内触发需与战斗层对接,是唯一有额外接口成本的场景。

### 1.9 技能体系(确认三分结构 + 学习成本决议)
- **升级成长(已确认)**:每级 **3 属性点**(分配到四维,维度可按需扩展)+ **1 技能点**。
- **学习成本(已确认,取代现状「点击即学」)**:学技能消耗技能点;单位系统设计.md 待定项「将来是否加技能点」就此关闭。
- **通用树**:计划按领域拆分为多棵小树(格斗、生存、剑、盾…),含**非战斗领域**以培养非战斗角色;非战斗角色经营地活动获取角色经验。
  - **老师门控收缩(已确认,推翻旧 🔒)**:大部分领域树节点**加点直接学**;仅**少量深层技能**需寻找特定 NPC/来源学习(精通的代价)。旧规格「所有通用技能初次获得必须有老师」作废——见 §4 文档同步。
  - ⚠ 「13 槽平铺 + 三色进阶区」现有 UI 是否/何时重构为领域小树:**待定**(见 §2.1)。SkillDB 的 `tree` 字段天然支持多树,数据侧成本低,主要是 UI 重做。
- **职业树**:`class_*` 同类共享树(与现状「职业技能」tab 占位对应);达到等级解锁层级,每层级学 1 个。
- **专属树**:具名角色(`char_*`)专用,替代职业树;随等级解锁、常选 1/N 分支(现状已有此规格)。
- **经验来源(已确认)**:战斗击杀为主;参战者结算时也获奖励经验;非战斗角色走营地活动。经验获取逻辑目前**未实现**(经验槽仅 UI)。
- **前置升级规则(已确认)**:带前置链的同名技能(训练有素 I→II→III)为**高级覆盖低级**,不叠加;可叠加者在描述中特别标注。
- 术语约定:
  - **skill** = 主动技能。每件武器至少 1 个 basic attack skill(= 普攻,借机/反击/援护均使用它)。部分武器有第二 skill,由精通类 perk 解锁(skill 归属 perk 而非武器本体)。
  - **perk** = 技能树节点,可为被动或解锁主动 skill。
  - **spell** = 魔法,独立体系(§1.10)。
- 职业树示例数据(帝国近战步兵线)见附录 A,可作数据格式参考,数值未定稿。

### 1.10 魔法系统(沿用既有设计 + 细化)
- 智力达标解锁魔法 tab;十字形 UI,四基础元素占四象限,夹角为次生元素(体验上近似八象限)。
- 魔法与角色等级无关,取决于智力 + 施法等级;需向 NPC/组织学习。
- 使用魔法积累对应**元素等级**经验;**施法等级 = 全部元素等级总和**。
- 次生元素魔法需两种相邻元素等级达标。
- 对立元素经验衰减:获取 1 点某元素经验,对立元素失去 0.5(相邻不受影响)。
  - **已确认**:施法等级为实时总和制,衰减会拖低施法等级。设计意图是约束而非禁止——对立双修可行但必然落后于专精者。

## 1.11 死亡规则:死门 + 重伤(规格已定)

**死门(Death's Door,战斗层新增)**
- **谁有死门**:玩家侧(我方/友方)全体 + 敌方**精锐/特殊单位**(数据标记,建议 tag);常规敌方单位 HP 归零照旧即死(`_handle_deaths` 原路径)。
- **进入**:HP 归零 → 进入死门状态,死门条 = 0(取值域 -3 ~ +3)。
- **每回合检定**(该单位 turn,自动执行):`1d20 + 体力` vs 难度;难度首回合 15,之后每回合 +5(15/20/25/30/35…)。过 +1,没过 -1。
- **受击**:仍在场占格、可被攻击;闪避与防御效能 **×50%**;被命中 -1。
- **死门期间**:无法移动、无法执行任何行动;敌方 AI 按既有「低血量 + 易命中」目标权重自然将其列为集火对象,无需特判。
- **结算**:
  - 条到 **-3**:非铁人 = **重伤离场**;铁人 = **真死**。两模式共用同一结算路径,仅结果不同。
  - 条到 **+3**:恢复行动能力,挂「重伤」debuff 至战斗结束(恢复时 HP 保底值待定,见 §2.3)。
- **代码对接点**:插在伤害落血归零与 `_handle_deaths` 之间;有死门标记的单位归零转入死门状态,无标记的走原移除路径。
- **实现注记**:`1d20 + 属性 vs 难度` 是项目首个属性检定原语,实现时抽成通用 `check(attr, dc)` —— 日后大地图/营地事件的属性检定(BB 式)直接复用。
- **救援**(内容层,后置):通用树将含救援类技能,直接将死门中的队友拉起。

**重伤/濒死休养**
- 战后持续一段时间无法参与任何活动(战斗、营地职务均不可);状态良好的单位可连续战斗。
- 设计基调:鼓励式而非惩罚式,不剥夺硬核玩家的选择权(铁人开关,默认关)。

## 1.12 角色面板扩展
