# 架构总览（一页地图）

> 全项目的**结构地图**：场景流 / 模块职责 / 数据流 / DB 约定 / 坐标序 / 核心理念。
> 新会话（或新人）先读这篇建立全局，再按需进 [实现现状.md](实现现状.md)（已做细节）/ [路线图.md](路线图.md)（未做 + 技术债）/ [单位系统设计.md](单位系统设计.md)（战斗规格 🔒）/ [属性与成长系统.md](属性与成长系统.md)（属性/成长/抗性/技艺真值 🔒）/ [表单-标签.md](表单-标签.md)（tag）。
> **约定**：架构级约定（DB 范式、坐标序、编辑器≠沙盒）只在本篇维护，其余文档引用不复述。

## 引擎 / 形态
- **Godot 4.6.2 stable（mono 引擎）+ 纯 GDScript**（无 C# 代码）。渲染 `gl_compatibility`。
- 网格：**平顶六边形（flat-top）+ odd-q 偏移**（奇数列向下错半格）。
- 主场景 = `StartMenu.tscn`（游戏正式入口）。

## 场景流
```
StartMenu.tscn（主场景 / 开始菜单）
 ├─ 战役 新开局/继续 → Overworld.tscn（大地图：移动=推时钟/扎营/事件；M4）   战役层
 │                      └ 新开局=WorldState.start_new / 继续=SaveIO 读 "auto" 槽
 ├─ 沙盒模式 → MapSelect.tscn（列 maps/*.json）→ Sandbox.tscn         自由测试场
 ├─ 编辑器（编辑·试玩）→ Game.tscn（双模式宿主：✎编辑 / ▶试玩）      关卡创作
 │                        └ 内嵌 MapEditor + Sandbox 两子场景，按 mode 切 visible/process
 ├─ 地图编辑 → MapEditor.tscn（独立入口，与 Game 内嵌为同一脚本）
 ├─ 物品编辑器 → ItemEditor.tscn（武器/防具/饰品增删改，写回 data/*.json）
 └─ 角色编辑器 → CharacterEditor.tscn（单位原型/预设增删改，写回 data/unit_prototypes.json）
```
- 跨场景传参用**静态单例**（`SandboxConfig.map_path`），不用 autoload / class_name。
- 三个 `.bat`（游戏 / Sandbox / 地图编辑器）用 `--path`+指定场景绕过主场景设置，各跑各的。

## 三个运行入口的职责边界 🔒
| 入口 | 定位 | 产出 |
|---|---|---|
| **MapEditor**（编辑器） | **创作可玩关卡**（authoring）：地形 + 这一关的单位 + 触发器 + 目标 | 一份持久关卡内容（地图 json） |
| **Sandbox**（沙盒） | **自由测试场**（testing）：任意召唤单位/物品验证机制手感 | 不落盘、临时 |
| **Game** | 统一宿主：编辑器 ↔ 试玩（内存直传当前关卡，免存盘往返） | — |

> **编辑器 ≠ 沙盒**：两者本质不同、**共用底层**（Unit / 造单位工厂 / DB / 画布基类），**不揉成一个**。别为「减少两套画布」强行合并。

## 模块地图（核心文件职责）
**战斗侧**
- `BattleState.gd`（**战斗模型层**，`RefCounted` 非 Node，2026-07-02 解耦 Phase 1~4）：战斗领域状态（棋盘/单位/回合/视野/环境/区域/触发账/击杀账/阶段胜负，30 字段）+ 纯规则方法（寻路 Dijkstra/ZOC/回合序/战斗结算 `_resolve_compute`/buff↔modifier 桥/死门/收尸/LOS 迷雾/AI 判定/targeting，53 个）+ **战中 suspend 快照 `to_dict()/restore()`**（单位主键=池下标 🔒）。**不认识 canvas/UI/场景树**；可脱离场景 headless 测（`tools/test_battlestate.gd`）。
- `Sandbox.gd`（~2300 行）：战斗**宿主**＝视图/输入/编排——持 `_state: BattleState`，模型字段经**同名转发属性**、规则经同名薄委托（画布 `editor.*` 契约与测试直调零破坏）；自留 日志/飘字/动画/UI 建造/回合与 AI 动作编排/环境叠层 + roster·预设 + `make_unit` 委托。→ 剩余拆分方向见 [路线图.md](路线图.md)「技术债」。
- **战中快照约定 🔒**（battle 层＝序列化第四层，与 proto/campaign 并列；原解耦规划护栏，2026-07-07 并入）：全量运行态原样存（位置/AP/移动点/effects/modifiers/死门条/skills{cd,uses}/ai_aggroed/tags＋技艺 prof_xp/known/slots）——`UnitFactory.unit_to/from_battle_snapshot`；**复原＝`Unit.new()` 后整份覆写**（绕开 make_unit 的 init_vitals 注满/learn_skill 充能重置/set_trait·equip 重挂陷阱）；**战斗内单位主键＝快照单位池下标**（uid 沙盒/预置单位恒 0 不可作键）；effects↔modifiers **整份原样存取**（source 保真、复原不重挂）；派生态不存（`_vis_visible`/区域派生 restore 重算，`_vis_seen` 唯一必存历史）。**新增运行态字段须同 PR 扩快照白名单**（to_dict/restore＋battle_snapshot 两处）。
- **画布契约护栏**：`SandboxCanvas` 直读宿主一批下划线私有（`_deploy_cells`/`_anim_*`/`_flash_units`/`_unit_hidden_by_fog`/`_has_acted`/`_is_active_unit`）——迁移必须在 Sandbox 保留**同名（含下划线）转发**；`hover_extra` 经 `has_method` 探测（MapEditor 故意不实现勿误加）；`faction_color` 在 Sandbox 与 MapEditor 各一份都要留。
- `Unit.gd`：单位数据模型——身份 / `tags` / `stats` 字典 / **修正管线 `modifiers`+`effective_stat`** / 装备 `equip`。
- `StatMeta.gd`：stat 键元数据**单一源**——键→中文标签 + 序列化/编辑器两白名单 + 物品禁键（`ITEM_FORBIDDEN_STATS`）。
- `SandboxCanvas.gd`（`extends HexCanvas`）：战斗画布，地形上叠单位 token + 血条 + 范围层 + 行动三态。
- `TurnOrderBar.gd`：顶部行动顺序槽。`UnitStatusPanel.gd`（**~1300 行**）：角色状态浮窗。`DeployPanel.gd`：单位编辑器。`RosterBar.gd`：布置期底部可用单位栏。

**战役侧（M4 起）**
- `Overworld.gd`：大地图场景宿主——队伍移动(Dijkstra)＝推进世界时钟 🔒 / 扎营 / enter_tile·timer 事件评估 / 日夜标签+tint / 自动存档 `auto` 槽。地图＝`maps/overworld/world.json`（`map_type:"overworld"`，`tools/gen_overworld_map.gd` 可再生成）。
- `OverworldCanvas.gd`（`extends HexCanvas`）：大地图画布，地形上叠队伍 token + 目的地标记；左键=移动指令。

**编辑器侧**
- `MapEditor.gd`（**巨石 ~1700 行**）：编辑器——UI / 画笔 / 存读 / 撤销 / **四图层（地形·区域·单位·触发器）** / 地形数据编辑。UI chrome（主题/分节/折叠/菜单/面板/确认框）退栈到 `EditorUI`+`EditorTheme` 公共层。
- `EditorCanvas.gd`（`extends HexCanvas`）：编辑器画布，地形上叠区域/单位层 + 按当前层分派左右键。
- `Game.gd`：双模式宿主（编辑↔试玩）。`ItemEditor.gd`（**~1000 行**）：物品编辑器（同退栈到 `EditorUI`+`EditorTheme`，深色观感与 MapEditor 一致）。

**Campaign 层（meta，2026-07-02 M1 起）**
- `WorldState.gd`：**campaign 聚合根**（纯数据 RefCounted，不认识场景）——时钟(小时计数🔒)/roster(活 Unit)/声望/flag/ironman + `to_dict/from_dict`；静态 `current`＝当前战役（null=沙盒等不建档🔒）；**`mint_uid()`＝unit/item 共用的存档域自增计数器🔒**。
- `SaveIO.gd`：**存读档单一入口**（仿 MapIO）——`user://saves/<slot>.json`，save/load/list/delete，版本 `.get` 兜底。
- `ItemInstances.gd`：**物品实例门面**——每件装备独立实例（词条/耐久/状态修正/强化次数载体）；`ItemDB` 降为纯模板源；战斗/UI 一律消费**合成视图 `view(uid)`**＝模板深拷⊕词条并入 mods。**库数据归属 WorldState 实例**（成员 `item_instances`），门面按 `current` 路由（无战役→独立临时库）——换档无全局副作用；存档只导出 roster 可达实例（GC）。`Unit.equipment` 存实例 uid（修正 source=`equip:<uid>:<序号>` 每条唯一）。模板热改语义 🔒＝运行期不重挂、读档/重装时生效。
- `WorldClock.gd`（M2）：**战外时间语义单一源**——`advance(ws, hours)`＝唯一推进入口（显式收档、不碰 `current`），逐小时结算调度表（恢复占位速率 ×M6 医生倍率；M7 据点刷新**不进调度**＝`LocationDB.site_ready` 惰性判定）；小时→日夜＝`EnvDB.time_for_hour`（`environment.json` times 的 `from_hour` 区间，消费端零改动）。**战斗不耗世界时间 🔒**：Sandbox 开战日夜＝地图显式 > 战役时钟 > 昼，退战回读时钟（夜进夜出）。
- `EventEngine.gd`（M3）：**when/do 事件引擎单一源**——①动作元数据注册表（运行时执行与编辑器表单同源，加动作只登记一处）；②执行＝参数解析 → 宿主原语转发（`event_*` 鸭子类型 + has_method 守卫）；③评估＝`enter_region/enter_tile/timer` + 闸门（once/chance/冷却/全局间隔）。**fired 状态两层 🔒**：战斗局部（宿主字典每战清零、ws=null 无冷却）vs 世界持久（`WorldState.event_*` 随档落盘）。
- `BattleIO.gd`（M5）：**战斗进出契约**——**快照进/结果出 🔒**（战斗操作 roster 序列化副本，campaign 只被 `apply_result` 显式回写＝根治双所有权）；`BattleSetup` 纯数据可序列化（战前选人 UI/预设队伍/食物 `provisions` 的地基）；`collect_result` 必须早于 `exit_battle` 回满；击杀统计入 `ws.kill_stats`（情报解锁输入源）。通道＝`SandboxConfig.battle_setup`（读后即清）。
- `Checks.gd`（M5）：**d20 检定唯一实现**——两形状：`check(unit, attr, dc)`＝1d20+effective 属性；`check_flat(bonus, dc)`＝调用方自算修正（死门求生＝5+body_fort/5 现用此形）；大地图/营地事件按取材复用。
- `JobDB.gd`（M6）：营地职务注册表（`data/jobs.json`）——指派状态在 `WorldState.camp_jobs`、在岗校验 `job_holder`（重伤不在岗）；加成承载 🔒＝改每小时速率（首个消费端＝WorldClock 医生倍率）。
- `LocationDB.gd`（M7）：地点类型/服务注册表（`data/locations.json`）——**定义/实例/状态三层分开**：实例在地图 `locations` 字段（编辑器/沙盒透传保真）、状态在 `ws.location_cleared_at`+`ws.gold`；据点刷新＝`site_ready` **惰性判定**（读时算，不进 WorldClock 调度）；讨伐闭环＝`BattleSetup.context{location_id}`→胜后 `apply_result` 落肃清账。
- `DialogueDB.gd` + `DialogueUI.gd`（M8）：对话数据（`data/dialogues.json`——node 图：纯演出/分支，选项效果 `set_flags`+`rep`，无档跳过）与通用对话控件（播放核心纯逻辑 headless 可测、UI 进树才建；全屏模态＝两侧立绘+文本+选项）。宿主接入唯一缝＝EventEngine `dialogue` 动作 → `event_dialogue(id)` 原语——大地图事件/地点交谈/战场内三场景同一份控件。
- `FactionDB.gd`（M9）：派系/声望注册表（`data/factions.json`）——**声望唯一读写口** `rep_of/add_rep`（start_rep 读端兜底+[-100,100] 钳制），数值存 `ws.reputation`（WorldState 纯存储不识派系）；`hostile()` 敌对判定；敌对遭伏＝Overworld 把敌对派系转成 enter_tile 伪触发器喂 EventEngine（冷却随档）。
- `WorldUnitDB.gd` + `WorldSim.gd`（🟡 v1）：大地图动态单位——类型定义（`data/world_units.json`）与模拟器（`tick(ws,hours,world)`＝**玩家移动=世界回合**，宿主鸭子接口不识场景节点）；实例随档存 `ws.world_units`；追上玩家→`BattleSetup.context{world_unit_uid}`→战胜移除。设计与待定 → [大地图动态单位.md](大地图动态单位.md)。

### Meta 层架构决策（🔒 已拍板 2026-07-02）
> Campaign 数据（WorldState）**不认识任何场景节点**——场景是它的消费者，与 BattleState 的解耦哲学同构。
1. **uid 生成规则 🔒**：存档域自增 int（`WorldState.next_uid`），unit/item 共用一个计数器（uuid 无必要）。
2. **时间粒度 🔒**：**按小时计数**——WorldClock ＝单调递增的小时计数器（本质是计数，非钟表模拟）。战外结算以「每小时」为节拍；营地职务加成＝**改变每小时速率**而非一次性触发；日夜＝小时区间 → EnvDB time id。
3. **存档 🔒**：campaign 正常存档（铁人 flag）；**战中存档＝「临时存档 suspend」语义**——只为退出后继续、**非 SL 读档**（读取即失效/覆盖式，防 save-scum）；**可裁剪**（麻烦就不提供）。
4. **战斗不消耗世界时间 🔒**：战场日夜**冻结**（夜里进战斗全程是夜）；战中只有天气变；退战环境复位＝回读 WorldClock 当前 time。
5. **sandbox 边界 🔒**：沙盒＝自由测试场**不挂** WorldState（临时实例、退出即弃），战役入口才建/载档——与「编辑器≠沙盒」同款边界。

**共用底层**
- `HexGrid.gd`：**纯六边形几何前置（single source）**——`RefCounted`+静态方法，cube 互转/距离/取整器/邻居/连线(`line`·`spoke_through`)/环外扩。无像素、无游戏规则依赖；Sandbox 逻辑几何 + HexCanvas 取整器均委托它（2026-07-02 解耦 Phase 0）。
- `HexCanvas.gd`：六边形画布基类（像素几何/拾取/缩放/平移/悬停 + 线特征 overlay + 边拾取 + 地点旗帜）——**不放任何一侧专属逻辑**，被 Editor/Sandbox/Overworld 三画布继承；取整复用 `HexGrid.cube_round`、地块绘制委托 `HexTileRender`。
- `HexTileRender.gd`：**地块渲染单一实现**（`RefCounted`+静态，2026-07-03）——`draw_tile(ci,center,size,color,accent,decor,seed)` 把「底色+黑描边+decor 线稿」画到任意 `CanvasItem`；三画布地图主循环与编辑器笔刷缩略图（`TerrainSwatch.gd`）共用，保证「笔刷格 == 地图格」。`seed=0`＝零扰动。
- `MapIO.gd`：**地图读写单一入口**（读文件/内存 normalize/写盘，统一尺寸钳制；写侧 `opts` 字典）。
- `DiagonalFrame.gd`：可复用对角装饰边框。`TextureCache.gd`：纹理加载+缓存单一入口。`tools/screenshot.gd`：通用截图 harness（窗口跑场景存 PNG，供 UI/美术目检）。
- `EditorTheme.gd` + `EditorUI.gd`：**编辑器公共 UI 单一实现**（2026-07-03）——`EditorTheme.build()` 统一深色 Theme（Button/OptionButton/MenuButton/Label/CheckBox/LineEdit/ItemList）+ `sb()`/`bg_color()` 工厂；`EditorUI` 控件工厂（`section_title`/`make_foldable`/`make_menu`/`panelize`/`background`/`field_row`/`add_line·check·spin`/`make_file_dialog`/`confirm`·`confirm_discard`）。全 `static`+preload 调用（不用 class_name，同 *DB）；**发信号的字段控件按 `on_change` 回调注入各编辑器刷新逻辑**——公共层不耦合具体编辑器。MapEditor / ItemEditor 均退栈到此层：chrome 单份实现、深色观感一致。加编辑器/加控件先看这层能否复用，别再各写一份。

## 数据层：DB 伪单例范式 🔒
所有 `*DB` + `MapIO` + `SandboxConfig` + `TextureCache` + **`WorldState`/`SaveIO`/`ItemInstances`（M1 新增）** 统一范式：**`extends RefCounted` + `preload` 常量引用 + `static var` 惰性加载 + 不用 `class_name`**（不用 class_name 是为 headless 可跑、免编辑器全局扫描）。⚠️ 若出现 preload 环（如 ItemInstances→WorldState→UnitFactory→Unit→ItemInstances），在环上一处改**运行时 `load()` 惰性引用**断环（先例：`ItemInstances._ws`）。⚠️ 惰性 `load()` 的字符串路径不被导出器依赖扫描追踪——**导出预设必须「导出全部资源」**（否则 WorldState.gd 不进包、首次装备即空引用）。
⚠️ **刷新函数不得叫 `reload`**：`XxxDB` 是 preload 的**脚本资源**，外部 `XxxDB.reload()` 命中的是原生 `Script.reload()`（重编译+静态变量全重置）而非你的静态函数——2026-07-02 实测踩坑；全 DB 统一 `reload_data()`。
用法：`const XxxDB := preload("res://XxxDB.gd")` → `XxxDB.方法()`。

| `AppearanceDB` | `data/appearance_parts.json`（换装部件/槽位/调色板；单文件 doc） | ✅ `slots/parts_in_slot/get_part/get_palette/canvas_size` | ✅ `save_part/delete_part/save_palette/reload_data`（外观工坊编） |
| `unit_prototypes.json` | `data/unit_prototypes.json`（单位原型/预设） | ✅ `UnitFactory.all_prototypes/get_prototype`（Sandbox/MapEditor/事件 spawn 消费） | ✅ `UnitFactory.save_prototype/delete_prototype`（角色编辑器编原型；仿 ItemDB） |

> **核心理念**：① **数据/代码分离**（真值外置 json，代码查表）；② **tag 统一判断**（单位/地块/物品/技能/效果共用 [表单-标签.md](表单-标签.md) 一张词表）；③ **修正是对象**（`Unit.modifiers` 保留载体 + buff/debuff 性质）。

## 地图数据流
```
maps/*.json ──MapIO.read_file──▶ {width,height,tiles,regions,units,triggers}
                                    │
              MapEditor 内存形 ◀────┤────▶ Sandbox 内存形（各按自己形态再转）
              (tiles/regions/         MapIO.normalize（内存 dict 直装，供 Game 试玩免存盘）
               map_units/map_triggers)
                                    │
              to_json_dict ──MapIO.write_map──▶ maps/*.json
```
- **地图 schema `format_version 4`**：现役可选字段 `map_type`（overworld/battle）/`units`/`regions`（含 `kind:aggro|deploy`）/`triggers`（when=enter_region·enter_tile·timer + 闸门；do=spawn_unit·activate_aggro·show_message·set_weather·dialogue·start_battle·add_rep·set_flag）/`terrain_overrides`（key=`terrain/variant`，只覆盖本图）/`environment`（time + weather_table）/`locations` /（**v4，线特征**）`rivers`·`roads`（`[{id,label,pairs}]`）·`bridges`（裸格对）——**格对＝相邻两格 `[[x,y],[x,y]]`，边键归一走 `HexGrid.edge_key`（无向）**；线特征通行语义**仅大地图**（`Overworld._move_cost_between`：河无桥硬阻断/桥·路 min(格成本,1)），战斗侧只渲染透传。**兼容套路**：加字段 + 读端 `.get(key,default)` 兜底，旧图零影响。`format_version` **仅人读标记、读端不强校验**——重新保存时才写成当前 FORMAT_VERSION。
- **写侧 API🔒**：`MapIO.to_dict/write_map(path,w,h,tiles,opts)`——可选字段收进 **`opts` 字典**（2026-07-03 从 11 位置参数收敛；再加字段不连坐全调用面）。`MapIO.peek_type(path)`＝轻量探测 map_type（列表过滤用，不跑全量 normalize）。
- **地形 `scope`（terrains.json 每条）**：`battle`/`overworld`/`both`（缺省 both）——**只过滤编辑器笔刷栏**（`TerrainDB.in_scope` 单一判定），渲染/通行照常认 tile，旧图越 scope 地形零破坏。
- **前瞻字段（未做草案）**：`effect_templates`（命名 effect 组合，做 effect/元素轮时填）、`cell_tags`（远期实例级 tag，稀疏 key=`"x,y"`）。
- 编辑器与 Sandbox **共享同一张 `res://maps/sandbox.json`**（编辑器改→打开沙盒即见）。

## 三套坐标序（最易踩的坑 ⚠️）
| 数据 | 顺序 | 含义 |
|---|---|---|
| `tiles[row][col]` | **行优先** [row][col] | 地形，共 height 行、每行 width 个 |
| `regions.cells[[x, y]]` | [x=col, y=row] | 区域格，`x` 是列 |
| `units[].col, .row` | 显式 col/row（odd-q） | 预置单位坐标 |

> **规约**：新字段一律**显式 `{col,row}` 或 `[col,row]`**，别再写反。像素↔格转换收敛在 `HexCanvas`（`hex_center`/拾取）与 `Sandbox`（`_hex_dist`/`NB_EVEN`·`NB_ODD` 邻居、战斗距离）各一份，职责不同不算重复。

## 修正管线（战斗数值地基）
`Unit.effective_stat(key)` = 面板基础 `base` +（三层解析）。装备/特性/buff/养成/地块 effect/元素 **都是「挂修正对象」的不同来源**。
- 修正对象 = `{stat, op, value, source, nature, tags?, duration?}`；层：`flat`（固定加）/ `pct`（%，基于基础相加）/ `eff`（效能，派生结果上连乘）。
- 战斗判定序 `_resolve_one` 与角色状态页均已全程读 `effective_stat`（仅 HP/armor 等运行时量走裸 `stats`）。
- **✅ 现状（2026-07-01 管线已通）**：flat/pct（去重取高）+ **eff 效能桶** `eff_mult`/`eff_reduce`（乘算·下限0）；伤害走 **`CombatResolver`** 分量化减伤链（甲抗 `armor_res_*`/人抗 `res_*`/固减 `dr_flat_*`，破甲溢出保留元素）；**buff↔modifier 桥**。**剩内容**（元素技能/附魔/防具甲抗数据/`def_eff`/`triple_vs`/地块effect）见 [路线图.md](路线图.md)「技术债」，规格见 [单位系统设计.md](单位系统设计.md)、[属性与成长系统.md](属性与成长系统.md)（属性/成长/抗性/技艺真值 🔒）。
