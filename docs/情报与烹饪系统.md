## 1. 敌方信息解锁系统（情报/图鉴）

核心理念：**信息是战利品，不是默认权利**。玩家对敌人的了解通过战斗积累，而非开局全知。

- **信息分层**：物理可见的信息免费（武器类型、持盾、护甲轻重、体型等战场肉眼可判断的事实，初见即显示）；隐藏信息需解锁（精确数值、技能机制、抗性表、隐藏特性）。**抗性表藏最深档**——试错学会「骷髅要用锤子」式的知识最有记忆价值。
- **解锁方式**：战后结算时根据**击杀记录**解锁。未解锁部分在查看敌方角色状态时显示为问号，**包括武器装备栏**。
- **图鉴**：营地分配**情报官**职务后解锁图鉴功能，可在非战斗状态随时查阅已解锁的敌人信息（**解锁引擎独立运作**，情报官的价值是「随时查阅」这个入口）。
- **编号与总量隐藏**：敌人模板统一编号，图鉴按编号排序；未遇过的敌人不出现在图鉴中——玩家看到编号 35，但不知道后面还有没有 36、37，**总量不可见**。
- 完全解锁（图鉴集齐某敌人全部层）可考虑给点奖励。

## 2. 烹饪与食物系统（怪物猎人猫饭模型）

核心理念：**食物是战备增益而非维持成本**。不吃无惩罚，吃了整场变强——拉力不是压力。

- **循环**：平时收集食材 → 营地烹饪（**消耗时间**）→ **战前选人阶段**消耗食物，为出战人员提供**持续整场战斗**的 buff。
- **食谱**：可收集，解锁对应食物的制作；高级食谱需要高级厨子。
- **厨子的构成 ＝ 烹饪技艺 + 其 perk 池投资**：烹饪＝技艺（生活页 10 域之一，阶段：生疏→大师，见 [属性与成长系统.md](属性与成长系统.md) §2）；解锁高级食谱、更高概率产出高品质食物、**食物分量变大**惠及更多人——均可做成烹饪 perk。
- **分量**：食物属性含分量——分量决定惠及的单位数量（大锅乱炖满足全员 vs 精致烩饭只够两三人）。分量与强度的取舍关系**待定稿**，方向是让战前配餐构成真实选择（广而弱 vs 窄而强）。
- **营地设施升级**可提高每次战斗能使用的食物数量。设施的数据挂载（队伍随行辎重 vs 地点）**待定**。
- **战前选人界面**：右侧花名册名单（计划支持**可保存的预设队伍**快速选取），左侧出战人员列表，食物在此阶段选用。
- **快捷料理（懒人兜底，内容性补充 2026-07-02）**：战前提供「快捷料理」选项——用最便宜的食材**当场烹饪**一份全员受益的简单食物，**加成极少但聊胜于无**；厨师能力会**略微**提高这一点。目的：不想经营食物线的玩家也不至于完全用不上系统（拉力不是压力理念的兜底面）。

## 3. meta 层铺垫分析（2026-07-02，对照 M1~M9 路线）

### 3.1 必须埋进 M5 的三处（一次投资多处受益）

1. **BattleResult 带 per-proto 击杀统计** 🔴 最关键
   M5 本来就要在 `_resolve_one/_handle_deaths` 加击杀记录点（经验结算用，现状死者 erase 即丢）。情报解锁的输入**正是同一份击杀记录**——BattleResult schema 直接设计成含 `kills: [{proto_id, by_uid}]`（或 per-proto 计数），战后结算一次遍历同时喂经验和情报解锁。若 M5 只记「击杀者→经验值」而丢掉 proto_id，情报系统上线时就要重开记录点＝返工。
2. **`_add_effect` 的 `permanent` 透传**
   现状写死 `permanent: false`（Sandbox._add_effect）。M5 死门要挂「至战斗结束」的 permanent effect 本来就要改；**食物 buff「持续整场战斗」也走同一机制**（permanent effect＋战斗结束 `_clear_effects_and_buffs` 清场，全部现成）。M5 改一次，两系统受益。
3. **BattleSetup 设计为纯数据可序列化 + 预留 `provisions` 挂点**
   战前选人界面（右花名册/左出战/食物选用/预设队伍）整个长在 BattleSetup 契约上：出战名单＝BattleSetup 主体；**预设队伍＝可保存的 BattleSetup 片段**（可序列化就白送）；食物选用＝BattleSetup 加 `provisions` 字段（M5 只留键位注释、不实现）。M5 设计 schema 时按「纯数据、可入档」标准做即可。

### 3.2 数据 schema 宜早定（防玩家可见后冻结返工）

- **敌人原型图鉴编号 `codex_id`**：unit_prototypes 加 int 编号字段（读端兜底可随时加）。⚠️ 铁律：**编号一经玩家可见即冻结**——图鉴上线前统一分配一次，之后新敌人只能追加编号，不得重排。分配动作放图鉴那轮，本条先立规矩。
- **库存模型方向（建议，待拍板）**：食材/食物＝**可堆叠消耗品**，建议走 `{item_id: count}` 计数模型（品质＝分档 id，如「炖菜·粗/良/精」三个 id），**不进 ItemInstances**——实例库继续只装「有个体状态的装备」（词条/耐久），职责不混。`WorldState.inventory` 字段到做的时候加（存档 `.get` 兜底范式，无迁移成本）；若将来某类食物真需要个体状态再个案升实例。
