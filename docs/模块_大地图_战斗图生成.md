# 模块_大地图_战斗图生成（临时·施工档 · 归宿＝模块_大地图 上半 + 模块_战斗 挂点）

> 状态：🟡 设计中（2026-07-11 用户发起）。**定位 🔒**：遭遇战地图＝按大世界上下文程序生成；**手工图留给特定关卡/副本/剧情战斗（用户自制）**——显式 `battle_map` 优先、无则生成。发起语境：现有"预设图摆敌人"（bandit_ambush.json）是火纹式线性关卡的轮子，不适合路遇性质的遭遇战。

## 1. 参考项目分析 ✅（2026-07-11 已啃源码）

[HextoryWorld/TiledProceduralHexTerrainGenerator](https://github.com/HextoryWorld/TiledProceduralHexTerrainGenerator)（JS+PIXI，`resources/js/source.js` ~800 行；上游=HTML5 Procedural Hexagon Terrain Generator，Red Blob/Amit 流派）：

- **双 simplex 噪声场**：elevation + moisture 各自独立 seed；**4 倍频叠加**（权重 `1 / 0.5 / 0.25 / 0.12`，频率 `1× / 4× / 8× / 16×`，基频 `frequencyElevation=0.8`）→ 归一 0..1 → **幂重分布** `pow(e, redistributionElevation)`（塑山地/平原占比）；可选 island 模式（中心距离衰减 `e=(1+e-d*3.5)/2`）。
- **高度分层×湿度选材**：`contourInterval_0..4` 切 6 档原型（深水/浅水/平地/丘陵/山地/不可越山）；每档内按 moisture 阈值选群系瓦片（平地：<0.10 荒漠 / <0.40 草 / <0.65 疏林 / <0.95 森林 / 其余沼林；山地类似），同档 `lookup()`(d100) 随机变体。
- **后处理**：孤立浅水（邻居无深水且浅水邻 <2）→ 湖泊瓦片；**lair 巢穴** 3% 撒在森林/丘/山/雪（我们的"劫道者营地"同族！）；火山=不可越山×低湿 3%；**河流**=高地采样源点顺低处流（riverSources→逐 hex 找更低邻）。
- 对齐结论：我们 terrains.json 的词表（grassland/forest/hill/mountain/sand/snow/shallow_water/deep_water/wasteland/bush）**天然可装进 elevation×moisture 矩阵**；线特征（河/路=edge 数据）比它的贴片河更结构化，生成后直接落我们的 schema v4。

## 2. 适配设计草案 🟡（待用户拍板后落 🔒）

**两个生成器共享一套引擎、两种驱动**（这就是"大地图生成≠战场生成"的答案）：

| | 大世界生成（远期，替 gen_overworld_map 手写图） | **遭遇战生成（近期目标）** |
|---|---|---|
| elevation/moisture 来源 | 纯噪声（照搬 Hextory 参数） | **锚点+梯度+低幅噪声**：遭遇格地形→(e,m) 特征锚点为均值；6 邻/3×3 地形做**方向梯度**（北邻是山→北缘 e 抬升）；噪声只做小扰动 |
| 尺寸 | 24×16+ | ~13×11（战斗尺度，可配） |
| 线特征 | 河源流+路网 | 遭遇格**过境才有**：道路→穿图曲线；河→一条边线河+桥 |
| 后处理 | 湖/巢穴/火山 | **战术校验**：双方部署带连通（Dijkstra 现成）、blocked 比例上限、掩体分布 |
| 单位 | 无 | 敌阵落位敌侧带（类型→`encounter_units` 数据化，数量随 power 缩放） |

**落地形状**：`BattleMapGen.gd`（纯 static，DB 范式）`gen(context, seed) -> MapIO dict`；**同 seed 同图**（可测/R 重开一致/suspend 可复现）；**内存直传不落盘**（Game 编辑↔试玩先例，需给 SandboxConfig 加一条内存图通道）。context＝{主地形 id, 邻域地形[6], 线特征过境旗, 时间天气, 敌阵表, seed}——Overworld `_start_battle_with` 处采样。
- 地形→(e,m) 锚点表：数据化（terrains.json 每地形加 gen 块 或独立 `data/battle_gen.json`——待定）。
- `encounter_units`：world_units.json 类型加键（marauders→bandit_* 组合）；`bandit_ambush.json` 降级为示例/兜底。
- **部署模式按战斗性质分**（用户 2026-07-11 补充，优先级低后置）：正常遭遇＝敌军生成对侧带、玩家在己侧自由部署；**伏击类＝敌人生成在玩家周围一圈**（环形落位、玩家部署区收窄居中）；context 加 `deploy_mode: "opposed" | "ambush"`（派系伏击/流寇拦路→ambush，engage 追上→opposed，后续可扩守卫战等）。
- 手工优先规则 🔒（用户 2026-07-11 已确认方向）：地点/剧情/触发器带显式 `battle_map` → 手工图；无 → 生成。

**分期**：v1＝锚点铺底+邻域梯度+斑块平滑+道路过境+敌阵落位+连通校验+测试（同 seed 同图/连通/比例）；v2＝河桥/掩体密度/高地；v3＝群系模板（雪原/沙漠遭遇性格化）+大世界生成器共享化。

## 2b. 前置排序 🔒（用户 2026-07-11 拍板：素材先行、生成器后置）

**战斗地图将引用独立素材地块（≠大世界地块），两套词表不完全对应**——火纹式小图/大图纹理分离（用户 2026-07-20 定调：FantasyHex 画风/规模过于宏观，只留大世界侧）。开工序：①战斗地块素材＝**已定（2026-07-20 用户购入 v0.6.5 DnD 六边形包**，作者已弃更、用户知情购入；单位素材仍自绘）→ ②素材入库+逐地块定义属性（入 terrains.json battle scope / 地块工坊线，含通行/成本/掩体/隐蔽等——编辑器地形数据区已支持 tags/effects 编辑）→ ③**才做生成器**。理由：生成器的输出词表＝战斗地形集，词表未定就建=返工。
架构推论（实现时用）：大世界地形 → 战斗地块的**对应关系不必一一映射**——它恰好就长在生成器的「锚点表」里（大世界地形 context → 战斗地块分布权重），一处数据两难自解；terrains.json 需支持 scope 区分（战斗专用地块不该出现在大世界笔刷，反之亦然——地块工坊已有 scope 过滤缝，现关闭中）。
