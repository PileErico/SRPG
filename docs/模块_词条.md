## ✅ 已实现（数据层就绪）

### 功能

- **affixes[] 实例字段**：每条＝`{name, mods:[{stat,op,value}], nature?}`；实例形/uid/库归属见 [模块_物品.md](模块_物品.md)。
- **add_affix 运行时护栏 🔒**：未知 stat 键（`StatMeta.is_valid_mod_stat` 白名单外＝永不被消费）或物品禁键（强韧 `will_fort`/`body_fort`）→ **整条拒收**+push_warning（带调用路径 ctx）。
- **读档自愈**：`parse_json`→`_sanitize_affixes` 逐条过同一校验——手编档/旧档违规词条读入即滤。
- **lint 双重执法**：`test_data_lint` 规则4 扫模板文件（weapons/armor/accessories）禁键；运行时护栏挡实例——禁键单一源＝`StatMeta.ITEM_FORBIDDEN_STATS`，严禁各处硬编码。
- **tooltip 可见**：`view()` 给词条 mod 打 `affix` 名标记 → `ItemTooltip.mod_line` 行尾注〔词条名〕。
- **source 烘焙约定 🔒**：词条/状态修正一律经 `view()` 并入 mods → `Unit._apply_item_mods` 烘焙 `equip:<iuid>:<n>`，卸装按 `equip:<iuid>` 前缀全摘；~~`affix:*`/`condition:*` 命名~~**作废**（另挂 source 脱离 unequip 前缀摘除→卸装泄漏）。
- 实例字段已留待消费：`condition`（""=无状态）/`enhance_count`（0）——铁匠轮接。

## 🟡 规划（原 词条系统.md 全篇设计；锻造/铁匠轮敲定 🔒 后实现）

**核心模型**：普通装备＝白板（common）无词条；差异来自两条独立词条来源维——

| 维度 | 来源 | 词条性质 | 归谁管 |
|---|---|---|---|
| 稀有度 rarity | 生成时 roll | 正面（越高越多/强） | 重铸（玩家转移） |
| 状态 condition | 生成时 roll | 负面 / 无 / 正面（单槽互斥） | 铁匠（修复/强化） |

- 稀有度＝既有 tag（common/uncommon/rare/epic/legendary/special，互斥取一）；显示稀有度只影响呈现层、不改实际 tag。
- 负面状态 → 负面词条＋**显示稀有度 −1**（边框/tooltip 抬头按降级显示；语义＝好货卖相变差，修好即恢复）；正面状态＝铁匠强化本质。

**待实现项**
- [ ] 生成 roll：① roll 稀有度→正面词条（白板无）→ ② roll 状态→负面/无/正面（概率分布待定）。
- [ ] 重铸（reforge）：词条从一件移到另一件（好词条挪到想穿的装备）。
- [ ] 铁匠（blacksmith）：修复＝移除负面状态、恢复显示稀有度（词条不受损）；强化＝施加正面状态（`enhance_count` 已留）；推论：状态单槽→强化前须先修复（待确认）。
- [ ] 铁匠 UI / 稀有度掉落（路线图「词条系统内容」；挂 M7 地点服务「铁匠」⏳planned 灰显位）。

**待定决策点（做那轮敲定 🔒）**
1. 词条池定义：预定义词条表（名字+mods+允许部位+稀有度门槛，倾向）vs 按 stat 程序随机。
2. 稀有度→词条曲线：每级几条正面词条、强度递增。
3. 状态分级：负面轻重（陈旧 vs 破损）；正面强化等级（+1/+2…）。
4. 状态单槽 vs 负面/正面并存多槽。
5. 重铸规则：可移词条范围（仅稀有度正面词条？）、部位匹配、损耗/次数/失败率、目标已有词条处理（覆盖/叠加/需空位）。
6. 显示降级呈现：仅边框色 vs 加破损角标/裂纹图标。

**硬约束（内容填充勿违规）**
- 词条 mods **禁 `will_fort`/`body_fort`** 🔒（强韧来源＝种族+perk 永不例外；双重执法已在上半）。
- 抗性词条**仅** `res_phys`/`res_nature` 及甲抗变体 `armor_res_*`。
- `dr_flat_*` 固减可用（§5 点名词条系统复用）。
- 词条＝modifier：复用 `effective_stat`/eff 桶管线，无新伤害数学；编辑器只维护白板模板，词条＝生成期附加、不手填。

**依赖链**：✅ 实例层 →（生成 roll）→ 铁匠/重铸 UI；均属锻造/经营内容层，排在战斗地基与编辑器主线之后。
