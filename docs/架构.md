# 架构总览（一页地图）

> 全项目的**结构地图**：场景流 / 模块职责 / 数据流 / DB 约定 / 坐标序 / 核心理念。
> 新会话（或新人）先读这篇建立全局，再按需进 [实现现状.md](实现现状.md)（已做细节）/ [路线图.md](路线图.md)（未做 + 技术债）/ [单位系统设计.md](单位系统设计.md)（战斗规格 🔒）/ [标签词典.md](标签词典.md)（tag）。
> **约定**：架构级约定（DB 范式、坐标序、编辑器≠沙盒）只在本篇维护，其余文档引用不复述。

## 引擎 / 形态
- **Godot 4.6.2 stable（mono 引擎）+ 纯 GDScript**（无 C# 代码）。渲染 `gl_compatibility`。
- 网格：**平顶六边形（flat-top）+ odd-q 偏移**（奇数列向下错半格）。
- 主场景 = `StartMenu.tscn`（游戏正式入口）。

## 场景流
```
StartMenu.tscn（主场景 / 开始菜单）
 ├─ 战役 新开局/继续 → Overworld.tscn（大地图：移动=推时钟/扎营/事件；M4）   战役层
 │                      └ 新开局=WorldState.start_new / 继续=SaveIO 读 "auto" 槽
 ├─ 沙盒模式 → MapSelect.tscn（列 maps/*.json）→ Sandbox.tscn         自由测试场
 ├─ 编辑器（编辑·试玩）→ Game.tscn（双模式宿主：✎编辑 / ▶试玩）      关卡创作
 │                        └ 内嵌 MapEditor + Sandbox 两子场景，按 mode 切 visible/process
 ├─ 地图编辑 → MapEditor.tscn（独立入口，与 Game 内嵌为同一脚本）
 └─ 物品编辑器 → ItemEditor.tscn（武器/防具/饰品增删改，写回 data/*.json）
```
- 跨场景传参用**静态单例**（`SandboxConfig.map_path`），不用 autoload / class_name。
- 三个 `.bat`（游戏 / Sandbox / 地图编辑器）用 `--path`+指定场景绕过主场景设置，各跑各的。

## 三个运行入口的职责边界 🔒
| 入口 | 定位 | 产出 |
|---|---|---|
| **MapEditor**（编辑器） | **创作可玩关卡**（authoring）：地形 + 这一关的单位 + 触发器 + 目标 | 一份持久关卡内容（地图 json） |
| **Sandbox**（沙盒） | **自由测试场**（testing）：任意召唤单位/物品验证机制手感 | 不落盘、临时 |
| **Game** | 统一宿主：编辑器 ↔ 试玩（内存直传当前关卡，免存盘往返） | — |

> **编辑器 ≠ 沙盒**：两者本质不同、**共用底层**（Unit / 造单位工厂 / DB / 画布基类），**不揉成一个**。别为「减少两套画布」强行合并。

## 模块地图（核心文件职责）
**战斗侧**
- `Sandbox.gd`（**巨石 ~2600 行**）：战斗宿主——回合机 / 移动寻路(Dijkstra) / 敌方 AI / ZOC 借机 / 攻击结算 / 技能 / 胜负 / 布置阶段 / roster / 预设 / **造单位工厂 `make_unit`·`_unit_to_proto`**。几何已委托 `HexGrid`。→ 拆分方向见 [路线图.md](路线图.md)「技术债」与 [解耦规划.md](解耦规划.md)。
- `Unit.gd`：单位数据模型——身份 / `tags` / `stats` 字典 / **修正管线 `modifiers`+`effective_stat`** / 装备 `equip`。
- `SandboxCanvas.gd`（`extends HexCanvas`）：战斗画布，地形上叠单位 token + 血条 + 范围层 + 行动三态。
- `TurnOrderBar.gd`：顶部行动顺序槽。`UnitStatusPanel.gd`（**~1300 行**）：角色状态浮窗。`DeployPanel.gd`：单位编辑器。`RosterBar.gd`：布置期底部可用单位栏。

**战役侧（M4 起）**
- `Overworld.gd`：大地图场景宿主——队伍移动(Dijkstra)＝推进世界时钟 🔒 / 扎营 / enter_tile·timer 事件评估 / 日夜标签+tint / 自动存档 `auto` 槽。地图＝`maps/overworld/world.json`（`map_type:"overworld"`，`tools/gen_overworld_map.gd` 可再生成）。
- `OverworldCanvas.gd`（`extends HexCanvas`）：大地图画布，地形上叠队伍 token + 目的地标记；左键=移动指令。

**编辑器侧**
- `MapEditor.gd`（**巨石 ~1700 行**）：编辑器——UI / 画笔 / 存读 / 撤销 / **四图层（地形·区域·单位·触发器）** / 地形数据编辑。
- `EditorCanvas.gd`（`extends HexCanvas`）：编辑器画布，地形上叠区域/单位层 + 按当前层分派左右键。
- `Game.gd`：双模式宿主（编辑↔试玩）。`ItemEditor.gd`（**~1000 行**）：物品编辑器。

**Campaign 层（meta，2026-07-02 M1 起）**
- `WorldState.gd`：**campaign 聚合根**（纯数据 RefCounted，不认识场景）——时钟(小时计数🔒)/roster(活 Unit)/声望/flag/ironman + `to_dict/from_dict`；静态 `current`＝当前战役（null=沙盒等不建档🔒）；**`mint_uid()`＝unit/item 共用的存档域自增计数器🔒**。
- `SaveIO.gd`：**存读档单一入口**（仿 MapIO）——`user://saves/<slot>.json`，save/load/list/delete，版本 `.get` 兜底。
- `ItemInstances.gd`：**物品实例门面**——每件装备独立实例（词条/耐久/状态修正/强化次数载体）；`ItemDB` 降为纯模板源；战斗/UI 一律消费**合成视图 `view(uid)`**＝模板深拷⊕词条并入 mods。**库数据归属 WorldState 实例**（成员 `item_instances`），门面按 `current` 路由（无战役→独立临时库）——换档无全局副作用；存档只导出 roster 可达实例（GC）。`Unit.equipment` 存实例 uid（修正 source=`equip:<uid>:<序号>` 每条唯一）。模板热改语义 🔒＝运行期不重挂、读档/重装时生效。
- `WorldClock.gd`（M2）：**战外时间语义单一源**——`advance(ws, hours)`＝唯一推进入口（显式收档、不碰 `current`），逐小时结算调度表（恢复占位速率；M6 职务速率/M7 据点刷新在 `_tick_hour` 扩展）；小时→日夜＝`EnvDB.time_for_hour`（`environment.json` times 的 `from_hour` 区间，消费端零改动）。**战斗不耗世界时间 🔒**：Sandbox 开战日夜＝地图显式 > 战役时钟 > 昼，退战回读时钟（夜进夜出）。
- `EventEngine.gd`（M3）：**when/do 事件引擎单一源**——①动作元数据注册表（运行时执行与编辑器表单同源，加动作只登记一处）；②执行＝参数解析 → 宿主原语转发（`event_*` 鸭子类型 + has_method 守卫）；③评估＝`enter_region/enter_tile/timer` + 闸门（once/chance/冷却/全局间隔）。**fired 状态两层 🔒**：战斗局部（宿主字典每战清零、ws=null 无冷却）vs 世界持久（`WorldState.event_*` 随档落盘）。

**共用底层**
- `HexGrid.gd`：**纯六边形几何前置（single source）**——`RefCounted`+静态方法，cube 互转/距离/取整器/邻居/连线(`line`·`spoke_through`)/环外扩。无像素、无游戏规则依赖；Sandbox 逻辑几何 + HexCanvas 取整器均委托它（2026-07-02 解耦 Phase 0，见 [解耦规划.md](解耦规划.md)）。
- `HexCanvas.gd`：六边形画布基类（像素几何/拾取/缩放/平移/悬停）——**不放任何一侧专属逻辑**，被 Editor/Sandbox 两画布继承；取整复用 `HexGrid.cube_round`。
- `MapIO.gd`：**地图读写单一入口**（读文件/内存 normalize/写盘，统一尺寸钳制）。
- `DiagonalFrame.gd`：可复用对角装饰边框。`TextureCache.gd`：纹理加载+缓存单一入口。

## 数据层：DB 伪单例范式 🔒
所有 `*DB` + `MapIO` + `SandboxConfig` + `TextureCache` + **`WorldState`/`SaveIO`/`ItemInstances`（M1 新增）** 统一范式：**`extends RefCounted` + `preload` 常量引用 + `static var` 惰性加载 + 不用 `class_name`**（不用 class_name 是为 headless 可跑、免编辑器全局扫描）。⚠️ 若出现 preload 环（如 ItemInstances→WorldState→UnitFactory→Unit→ItemInstances），在环上一处改**运行时 `load()` 惰性引用**断环（先例：`ItemInstances._ws`）。⚠️ 惰性 `load()` 的字符串路径不被导出器依赖扫描追踪——**导出预设必须「导出全部资源」**（否则 WorldState.gd 不进包、首次装备即空引用）。
用法：`const XxxDB := preload("res://XxxDB.gd")` → `XxxDB.方法()`。

| DB | 数据文件 | 读 | 写回 |
|---|---|---|---|
| `TerrainDB` | `terrains.json` | ✅ | ✅ `save/reload` |
| `ItemDB` | `data/{weapons,armor,accessories}.json` | ✅（**纯模板源**；运行时物品一律经 `ItemInstances.view(uid)` 合成视图） | ✅ `save_item/delete_item/reload`（物品编辑器编模板） |
| `ItemInstances` | —（实例态，随 campaign 档 `user://saves/` 序列化） | ✅ `view(uid)`/`get_instance` | `create/add_affix/destroy/load_json` |
| `TagDB` | `data/tags.json`（55 tag/12 类，标签词典机器可读版） | ✅ `cn/color/by_cat` | reload |
| `SkillDB` | `data/skills.json` | ✅ | 只读（按需补） |
| `TraitDB` | `data/traits.json` | ✅ | 只读（按需补） |
| `unit_prototypes.json` | — | 由 `Sandbox`/`MapEditor` **直接文件读**（尚无专用 DB） | — |

> **核心理念**：① **数据/代码分离**（真值外置 json，代码查表）；② **tag 统一判断**（单位/地块/物品/技能/效果共用 [标签词典.md](标签词典.md) 一张词表）；③ **修正是对象**（`Unit.modifiers` 保留载体 + buff/debuff 性质）。

## 地图数据流
```
maps/*.json ──MapIO.read_file──▶ {width,height,tiles,regions,units,triggers}
                                    │
              MapEditor 内存形 ◀────┤────▶ Sandbox 内存形（各按自己形态再转）
              (tiles/regions/         MapIO.normalize（内存 dict 直装，供 Game 试玩免存盘）
               map_units/map_triggers)
                                    │
              to_json_dict ──MapIO.write_map──▶ maps/*.json
```
- **地图 schema `format_version 3`**（可选字段 `units`/`regions`/`triggers`/`terrain_overrides`）。**兼容套路**：加字段 + 读端 `.get(key,default)` 兜底，旧图零影响。`format_version` **仅人读标记、读端不强校验**——存量老图文件头可能仍是旧值（如 `maps/sandbox.json`=1），**重新保存时才写成当前 FORMAT_VERSION**。
- 编辑器与 Sandbox **共享同一张 `res://maps/sandbox.json`**（编辑器改→打开沙盒即见）。

## 三套坐标序（最易踩的坑 ⚠️）
| 数据 | 顺序 | 含义 |
|---|---|---|
| `tiles[row][col]` | **行优先** [row][col] | 地形，共 height 行、每行 width 个 |
| `regions.cells[[x, y]]` | [x=col, y=row] | 区域格，`x` 是列 |
| `units[].col, .row` | 显式 col/row（odd-q） | 预置单位坐标 |

> **规约**：新字段一律**显式 `{col,row}` 或 `[col,row]`**，别再写反。像素↔格转换收敛在 `HexCanvas`（`hex_center`/拾取）与 `Sandbox`（`_hex_dist`/`NB_EVEN`·`NB_ODD` 邻居、战斗距离）各一份，职责不同不算重复。

## 修正管线（战斗数值地基）
`Unit.effective_stat(key)` = 面板基础 `base` +（三层解析）。装备/特性/buff/养成/地块 effect/元素 **都是「挂修正对象」的不同来源**。
- 修正对象 = `{stat, op, value, source, nature, tags?, duration?}`；层：`flat`（固定加）/ `pct`（%，基于基础相加）/ `eff`（效能，派生结果上连乘）。
- 战斗判定序 `_resolve_one` 与角色状态页均已全程读 `effective_stat`（仅 HP/armor 等运行时量走裸 `stats`）。
- **✅ 现状（2026-07-01 管线已通）**：flat/pct（去重取高）+ **eff 效能桶** `eff_mult`/`eff_reduce`（乘算·下限0）；伤害走 **`CombatResolver`** 分量化减伤链（甲抗 `armor_res_*`/人抗 `res_*`/固减 `dr_flat_*`，破甲溢出保留元素）；**buff↔modifier 桥**。**剩内容**（元素技能/附魔/防具甲抗数据/`def_eff`/`triple_vs`/地块effect）见 [路线图.md](路线图.md)「技术债」，规格见 [单位系统设计.md](单位系统设计.md)。

## 运行 / 自测
- 启动：`run_game.bat` / `run_sandbox.bat` / `run_map_editor.bat`，或 VSCode `Ctrl+Shift+B`。
- **headless 自测**：`..._console.exe --headless --path "D:/1战棋" res://<场景>.tscn --quit-after 8`（跑真实场景、必然自动退出、stderr 看报错）。
- ⚠️ **不要写不调 `quit()` 的 SceneTree 脚本**（会空转不退出）；`add_child` 后 `_ready` 延迟、需显式初始化。
