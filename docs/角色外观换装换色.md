# 角色外观：分层换装 + 亮度换色（独立模块）

> 定位 🔒（2026-07-03）：一个**独立、数据驱动**的角色外观合成模块。开发者/玩家用**分层部件拼装**（换装）+ **亮度→调色板渐变**（换色）组合出角色形象。**唯一对外产物 = 导出的单张 PNG**；游戏其他模块经现有 `Unit.portrait`/`Unit.icon` 路径字段消费——**本模块不改地图/战斗渲染管线**（彻底解耦）。技术源自网页工具 EasyChar（PSD 分层 + SVG 灰度→渐变），移植进本工程并按本工程范式重做。

## 🔒 已锁定决策
- **解耦**：产物＝PNG；分层只是**编辑态**，导出＝烘焙成一张图。MVP **不碰** `Unit.gd`/`UnitFactory`（避开三窗并行高频共享文件）。
- **正面单张**：无四方向、无行走动画（部件按固定尺寸/锚点设计，为未来动画**预留**但现在不做）。
- **换色＝shader 思路的 CPU 实现**：MVP 用 GDScript 直接操作 `Image` 烘焙（确定性、可 headless 测试）；实时预览也走同一 `Image` 重算（32×32 足够快）。GPU shader 预览＝P2 可选加速。
- **部件原生 32×32**（DB `config.size` 可配置，改不返工）；**所有部件同尺寸同锚点**才能叠齐。
- **开发者优先**：部件素材由开发者添加（画/导入）；玩家只**拼装+换色+导出**、不画素材。
- **创作器＝独立场景「外观工坊」**（主菜单进，与物品/角色/地图编辑器平级）。

## 数据格式：`data/appearance_parts.json`（单文件 doc）
```json
{
  "config": { "size": 32 },
  "slots":   [ {"id":"body","cn":"身体","z":0}, ... ],           // z 升序＝从后到前叠放
  "parts":   [ {"id":"body_human","slot":"body","cn":"人类",
                "path":"res://icons/Parts/body/human.png",
                "tags":["human"],"recolorable":true,"default_palette":"skin_pale"}, ... ],
  "palettes":[ {"id":"skin_pale","cn":"浅肤","stops":["#20140f","#7a4a38","#e8b48c","#fff1e0"]}, ... ]
}
```
- 槽位含 **`body` 底子槽**，变体按 `tags` 复用 [标签词典](标签词典.md) 的种族词表（human/undead/lizardmen…）——**不新造字段**。
- 部件贴图存**灰度源**（含明暗层次），运行时按亮度映射到调色板渐变 → 免多发 PNG（取代蜥蜴人 Blue/Green/Yellow 三张的老做法）。
- 颜色存 **hex 字符串**、id 走 `[A-Za-z0-9_]`（规避 JSON int/float 抖动，同工程约定）。

## 合成 / 换色算法（`PaperDoll.gd`，纯静态）
- **配方** `recipe := { "parts":{slot:part_id}, "palettes":{slot:palette_id} }`。缺槽=不画；缺调色板=用部件 `default_palette`；部件 `recolorable=false`=原样。
- **换色** `recolor(img, stops)`：逐像素 `l = dot(rgb, (0.299,0.587,0.114))`（Rec.601），在 N 个色标间线性插值取色，**透明像素保持透明**、alpha 透传。纯函数、返回新 Image。
- **合成** `compose(recipe)`：按 `AppearanceDB.slots()` 的 z 序，逐槽 `_part_image`（经 `TextureCache`）→ 换色 → `Image.blend_rect` 叠到 32×32 底图。
- `bake(recipe)→ImageTexture`（按配方签名缓存）；`export_png(recipe, path, scale)`（最近邻放大）＝**对外产物**。

## 模块文件
| 文件 | 职责 | 范式 |
|---|---|---|
| `data/appearance_parts.json` | 部件/槽位/调色板真值单一源 | 数据 |
| `AppearanceDB.gd` | 读/查/upsert 部件·调色板 | `extends RefCounted`+static+无 class_name，`reload_data`（仿 ItemDB/TerrainDB） |
| `PaperDoll.gd` | 换色/合成/烘焙/导出核 | static 无状态（仿 HexTileRender/TextureCache） |
| `AppearanceWorkshop.gd/.tscn` | 开发者创作器 UI（独立场景） | 复用 EditorUI/EditorTheme，纯代码建 UI |
| `PixelDrawCanvas.gd` | 内置像素画布（铅笔/橡皮/填充/吸管 + 洋葱皮对齐 + undo） | `extends Control`，未来完整像素编辑器的地基 |
| `icons/Parts/<slot>/*.png` | 部件贴图（32×32 灰度；工坊内绘制/导入均落此） | 素材约定 |
| `tools/test_appearance.gd` | headless 回归（DB 往返 + 换色纯函数 + 合成/导出） | 仿 test_itemdb（`_path_override` 缝） |

## 外观工坊 UI
左＝逐槽位折叠：部件缩略图网格（按默认盘染色预览 + `∅ 无`）+ 每槽调色板 swatch 行，金框选中。右＝棋盘格底大预览（实时合成）+ 随机/重置 + 导入部件 PNG（选槽）+ 文件名/倍数/导出 PNG。**序列化只经 AppearanceDB 单一口**。

## 接入其他模块（解耦点）
本模块只产 PNG。**闭环已落地**：工坊「🎭 应用到单位…」→ 选原型 → 导出 PNG 到 `res://icons/Characters/appearance_<id>.png` + 设该原型 `portrait`/`icon`（走 `UnitFactory.get_prototype`/`save_prototype` **公开口，不改共享文件**）+ 存配方到 `data/appearance_looks.json`（`AppearanceDB.save_look/get_look/all_looks`）；「📥 从单位载入外观」回读配方继续编。**不给 `Unit` 加字段、不改 `SandboxCanvas._draw_icon`、不穿 3 条序列化往返口**——单位仍走现有 `portrait`/`icon` 路径消费。正好取代 `lizardmen_yellow/blue` 等「靠多发 PNG 换色」的老做法。

## 外观组：一个角色多套立绘+棋子（成对绑定 · ✅ 编辑器管理已落地 2026-07-05）

> 目标：给一个角色**同时挂多套「立绘 + 棋子」外观**，供后续按条件切换（形态变换如狼人 / 特定敌人高级版立绘…）。**本步只做「在角色编辑器里增删/命名/管理多套外观」；引用与引用条件 = 下一步（🟡 见下）。**

**成对绑定 🔒**：一套外观 = 一张立绘 + 一个棋子，捆在一起整套切换（狼人「狼形」= 狼立绘 + 狼棋子一起换）。非「立绘池 / 棋子池自由组合」。

**数据（proto 层，`unit_prototypes.json`）**——加两个**可选**字段，顶层 `portrait`/`icon` 保留作「默认外观」镜像：
```json
"appearances": [
  {"id":"base", "name":"常态", "portrait":"res://…", "icon":"res://…"},
  {"id":"wolf", "name":"狼形", "portrait":"res://…", "icon":"res://…"}
],
"default_appearance": "base",
"portrait":"…",   // = 默认外观的立绘（旧字段保留 → 落子/大地图/战斗渲染零改动）
"icon":"…"        // = 默认外观的棋子
```
- **向后兼容 🔒**：只有 >1 套时才写 `appearances`/`default_appearance`；单套 = 旧格式（顶层 portrait/icon），既有原型零 diff。载入时缺 `appearances` → 用顶层字段合成一条 `base`。
- **解耦 🔒**：`appearances` 是**编辑器侧状态**，经 proto 出入——**`Unit.gd` / `UnitFactory.gd` 一行未改**（`save_prototype` 整字典透传、`_intify` 递归）。`CharacterEditor._collect_proto` 挂回 proto + 让顶层 portrait/icon 镜像默认外观；`_init_appearances` 读回。仿 `_bag` 的「编辑器态、不入 Unit」处理。

**编辑器（`CharacterEditor` 外观组区）**：strip 里「外观组」一行 = chip 行（每套缩略：立绘→退棋子→淡显；★=默认、金框=当前编辑）+ `＋添加外观 / 设为默认★ / ✕删除当前` + 选中套的 `外观 id`（引用条件用，回车/失焦提交唯一校验）/`名称`。选中某套 → 卡片头像「＋」改它的立绘、下方「棋子图标」改它的棋子（**复用现有两个文件选择器，零新增对话框**）；改图即写回该套。回归：`test_chareditor` 加数据往返 + 编辑器逻辑两块（全 PASS）。

**🟡 下一步（待设计再实现）——引用与引用条件**：一个解析器按条件选中激活的外观 form，把它的 portrait/icon 写回 `Unit.portrait`/`icon`（下游照旧读，渲染管线不动）。条件类型初步：运行时 tag（`transformed` → 狼形，可逆）/ 生成时世界条件（章节·我方等级·难度 → 敌人高级版，生成即定）。⚠️ **战斗中不升级**（升级仅战间成长）→ 等级类条件的触发放战间结算、不在战斗内。见对话记录，敲定后补此节。
